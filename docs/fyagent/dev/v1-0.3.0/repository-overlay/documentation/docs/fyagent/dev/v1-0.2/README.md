## 1. 文档目的

本文档包针对当前 FyAgent 私有分支中已经确认的产品问题，给出可直接进入实施的需求、交互、架构、数据、安全、变更地图和测试设计。核心范围包括：

1. Codex 桌面应用无法唯一确认时，由弱提示改为用户决策对话框，并支持受约束的强制重启；
2. WorkBuddy 页面增加已有模型 ID 查看、即时搜索、覆盖确认、API Key 内存保留和官网下载入口；
3. 修复 WorkBuddy 页面白边、顶部栏大范围位移以及右上角 `+` 被裁剪；
4. 将 Codex/ChatGPT 桌面应用版本号的加载、刷新和错误状态显式建模；
5. Windows 正式版默认请求管理员权限，并补齐安装、签名、子进程权限、单实例、外链和 IPC 安全边界；
6. 建立可重复的桌面 E2E、几何断言和关键区域视觉回归验收体系。

本文档只描述设计与验收，不修改项目源码，也不包含人员、工期或 PR 分工。

## 4. 术语约定

### 4.1 Codex 桌面应用

OpenAI 于 2026-07-09 宣布 Codex 应用并入新的 ChatGPT 桌面应用；原 Codex 应用更新后会成为新的 ChatGPT 桌面应用，而此前的 ChatGPT 桌面应用改名为 ChatGPT Classic。

本文首次出现时使用：

> **Codex 桌面应用（更新后显示为 ChatGPT）**

后续简称“Codex 桌面应用”。本文目标不包括 ChatGPT Classic，也不包括 Codex CLI、IDE 插件或名称相似的其他进程。

### 4.2 “不允许第二个实例”

本要求指：

- 任意时刻只允许一个完成业务初始化的 FyAgent 实例；
- Windows UAC 之后允许出现极短生命周期的激活进程；
- 激活进程不得初始化 WebView、数据库、托盘、代理服务或其他业务模块，只能转发激活请求后立即退出；
- 不允许第二个可见窗口，不允许两个进程同时读写业务配置。

### 4.3 用户界面与诊断信息

用户界面优先使用简单、直接的结果描述。PID、包族名、Bundle ID、安装路径、错误阶段、候选数量等信息只进入脱敏诊断日志，不直接展示给普通用户。

## 5. 总体设计原则

1. **后端拥有事实判定权。** 进程身份、配置 revision、安装目标、权限级别和写入结果不得由前端猜测。
2. **前端只持有最小状态。** 不向 WebView 返回 PID、句柄、完整系统路径或任意进程启动能力。
3. **用户操作保持原子。** 配置保存、已有模型覆盖和 `availableModels` 更新必须作为同一事务提交。
4. **失败时不伪装成功。** 配置已保存和重启失败必须分开表达；后台刷新失败不得伪装为刷新成功。
5. **默认复用现有原语。** 继续使用现有 `Button`、`Input`、`Checkbox`、`Card`、`Dialog`、`Popover`、`ScrollArea` 等组件，不新建第二套基础组件。
6. **响应式而非裁剪。** 顶部栏必须按优先级收纳，关键操作永不依赖父元素 `overflow-x-hidden` 侥幸可见。
7. **管理员权限不向外扩散。** Windows 主进程虽为管理员，但浏览器、终端、编辑器和普通桌面应用默认以交互用户普通权限启动。
8. **自动化证据可追溯。** 几何数据、截图、差异图和日志应可定位到需求编号，并经过脱敏。

## 6. 最终范围摘要

### 6.1 Codex 重启

- 多安装、多运行实例和实例身份无法唯一绑定时，不再只显示 Toast；
- 显示一次强制关闭并重启确认；
- 执行时重新枚举所有精确匹配实例，强制关闭全部实例，只启动一个安装；
- 任一实例未关闭则不启动新实例；
- 失败界面只显示“配置已保存，但 Codex 重启未完成。”并提供重试或手动重启。

### 6.2 WorkBuddy

- 同时支持旧根数组和对象根 `{ "models": [...] }`；
- 独立展示静默去重后的已有模型 ID；
- 已有模型仍可选中并覆盖，所有远程模型获取后默认选中；
- 覆盖只更新 `url` 和 `apiKey`；
- API Key 在当前页面内存中保留，离开页面时清空；
- 下载按钮固定打开 `https://www.workbuddy.cn/`；
- 搜索输入变化后立即过滤，不需要搜索按钮。

### 6.3 桌面布局与窗口

- WorkBuddy 删除页面级 `max-w-4xl` 居中窄栏；
- 顶部栏顺序固定为：品牌、P1、P2/更多、AppSwitcher、最右主操作槽；
- Provider 页面主操作槽显示 `+`，WorkBuddy 使用完全同宽的不可交互空槽；
- 正常最小宽度由自动布局测量得出；小工作区进入响应式兜底，而不是将窗口挤出屏幕。

### 6.4 Windows

- 正式主程序使用 `requireAdministrator`；
- 正式 Windows 产物必须 Authenticode 签名；
- per-machine 安装，默认 Program Files，允许经过安全校验的自定义本地目录；
- 停止发布 Portable 绿色版；
- Windows 禁用开机自启，但保留默认关闭到托盘；
- 深链接和局域网代理能力继续保留，相应风险列入已接受风险。

## 7. 使用顺序

实施人员应按以下顺序阅读：

1. 先以 [01](./01-需求规格与决策基线.md) 确认产品边界；
2. 用 [02](./02-现状分析与代码证据.md) 对照当前代码；
3. 前端实现参考 [03](./03-交互设计与状态矩阵.md)；
4. 前后端接口和平台服务参考 [04](./04-系统架构与IPC设计.md)；
5. WorkBuddy 文件写入必须遵循 [05](./05-WorkBuddy数据模型与安全设计.md)；
6. 按 [06](./06-实施顺序与仓库变更地图.md) 的依赖顺序修改；
7. 最终以 [07](./07-验收标准与自动化测试计划.md) 判定完成；
8. 对架构取舍或风险有疑问时查阅 [08](./08-ADR与外部资料.md)。
