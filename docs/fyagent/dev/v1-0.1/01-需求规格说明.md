# 01 — 需求规格说明

## 1. 文档目的

定义私有分支 `feature/fyagent-v1` 上新增 Codex 供应商能力、Codex 桌面应用重启询问以及 WorkBuddy 一键模型配置页的完整产品要求。本文是验收和详细设计的上位依据，不包含实施排期或任务分工。

## 2. 背景与目标

当前分支已具备多应用供应商管理、Codex 配置编辑、供应商切换、Codex 桌面安装/启动、通用模型列表获取和通用模态框。目标是在不破坏现有供应商体系的前提下：

1. 对所有 Codex 供应商提供可视化、可编辑的生图请求头和 WebSocket 能力配置；
2. 在 live Codex 配置改变后，提供可控且身份可信的桌面应用重启流程；
3. 为 WorkBuddy 提供独立、低风险、可批量写入第三方模型的配置入口；
4. 对用户手工维护的 TOML/JSON、注释、未知字段和凭据提供非破坏式处理。

## 3. 范围

### 3.1 包含

- Codex 新增/编辑供应商表单中的两个供应商级开关；
- Codex TOML 双向解析、无损补丁和冲突提示；
- 历史 Codex 供应商的延迟迁移状态；
- live 配置实际变化后的重启询问；
- Windows、macOS 上可信 Codex 桌面应用的运行检测、正常退出、可选强制退出、启动和成功确认；
- WorkBuddy 顶层导航、图标、显示设置；
- WorkBuddy URL、API Key、模型获取、模型选择、手动模型、批量 upsert；
- `~/.workbuddy/models.json` 的校验、单份备份、原子替换、未知字段保留和冲突处理；
- 中英日及繁体中文界面文案；
- 可判定的验收场景。

### 3.2 明确排除

- 新增 Codex 全局“高级配置”页面；
- 将生图扩展或 WebSocket 作为全局开关；
- 处理 Codex CLI、IDE 插件或任意名称包含 Codex 的进程；
- 自动安装、检测版本、升级、启动、关闭或重启 WorkBuddy；
- WorkBuddy 完整模型管理列表、删除、拖拽排序或逐模型显示名编辑；
- WorkBuddy 项目级配置；
- 读取或兼容 `~/.codebuddy/models.json`；
- WorkBuddy MCP、Skills、Prompt、Session、Profile、用量或代理接管；
- 非标准 `/models` 响应格式猜测；
- 公开上游 cc-switch 的升级或合并方案；
- 开发任务、工期、人员和 PR 拆分。

## 4. 用户与前置条件

### 4.1 Codex 用户

- 已在本应用中新增或编辑任意 Codex 供应商，包括固定官方、保留名称、普通第三方、Codex OAuth、xAI OAuth 等托管身份；
- 供应商 TOML 草稿整体可解析时，均可操作两个能力开关；
- 代理接管可处于开启或关闭状态，代理场景不构成保存门禁。

### 4.2 WorkBuddy 用户

- 不要求 WorkBuddy 已安装；
- 用户有权修改其主目录下的 `.workbuddy`；
- 上游端点为 OpenAI-compatible 模型列表接口；
- 用户自行确认第三方服务的安全、费用和合规性。

## 5. Codex 功能需求

### 5.1 适用范围判定

**CDEX-FR-001** 只要应用为 Codex，系统就应显示两个开关。不得使用 Provider ID、名称、`base_url`、凭据类型、官方/托管分类、OAuth 身份、代理接管、`wire_api` 或 `meta.apiFormat` 作为隐藏或只读门禁。

固定官方供应商只由 `category = "official"` 或固定 ID `codex-official` 判定，不得根据名称 `OpenAI`、`requires_openai_auth` 或 URL 推断。

### 5.2 UI 位置

**CDEX-FR-002** 两个开关应同时出现在新增和编辑供应商表单的现有“高级选项”折叠区，建议分组名为“Codex 原生能力”。不新增独立页面。

**CDEX-FR-003** 分组包含：

- `启用内置生图扩展`；
- `启用 WebSocket 传输`。

高级区域初始保持折叠，不因能力开启、冲突或待迁移自动展开；折叠提示必须明确包含两个能力入口。

### 5.3 内置生图扩展

**CDEX-FR-004** 固定官方供应商缺少显式配置时生图默认关闭；其他新建 Codex 供应商默认开启。已存在的显式 TOML 始终优先。开启并保存后在对应供应商表中合并：

```toml
http_headers = { "x-openai-actor-authorization" = "local-image-extension" }
```

**CDEX-FR-005** 开启时删除所有大小写不敏感匹配的同名键，写入唯一规范键；合法字符串映射中的其他请求头保持不变。

**CDEX-FR-006** 关闭时删除所有大小写不敏感匹配的同名键，不论旧值为何；其他合法请求头不变。若映射因此为空，删除 `http_headers` 字段。

**CDEX-FR-007** 若存在大小写冲突、错误值或重复变体，UI 应显示不含请求头值的诊断。普通保存原样保留；用户主动开启时覆盖为唯一规范键，主动关闭时删除全部变体。若 `http_headers` 不是合法字符串映射，主动开启时整体替换为只含受管请求头的新映射，主动关闭时整体删除；不得由无关保存触发该修复。

**CDEX-FR-008** 目标请求头名称匹配应大小写不敏感；值匹配应精确。

### 5.4 历史供应商延迟迁移

**CDEX-FR-009** 升级后不得批量改写历史供应商或 live 配置。

**CDEX-FR-010** 对历史非官方供应商，引入私有元数据 `imageExtensionConfigured`：

- 元数据缺失、无同名请求头且无冲突：首次打开编辑页时，开关显示开启但仅为“待迁移”草稿；
- 用户保存且保持开启：写入目标请求头，并将元数据设为 `true`；
- 用户保存前关闭：不写请求头，并将元数据设为 `true`，表示明确关闭；
- 已存在目标请求头：显示开启，保存时补齐元数据；
- 已存在冲突请求头：显示冲突，不自动迁移，不擅自改写冲突值。

**CDEX-FR-011** 新建供应商应从第一次保存起写入 `imageExtensionConfigured: true`，避免被误判为历史待迁移。

### 5.5 WebSocket 能力

**CDEX-FR-012** 新建和历史供应商的 WebSocket 开关默认关闭。

**CDEX-FR-013** 开启时，在对应供应商表写入：

```toml
supports_websockets = true
```

**CDEX-FR-014** 关闭时删除该字段，不写 `supports_websockets = false`。

**CDEX-FR-015** WebSocket 是允许自由配置的 Provider 字段：

- Responses、Chat Completions、Anthropic、固定官方、托管 OAuth 和代理接管场景均可开启并保存；
- API 格式变化不得自动关闭、删除或改写 `supports_websockets`；
- `supports_websockets` 类型异常时显示诊断但允许普通保存；用户主动开启时覆盖为布尔 `true`，主动关闭时删除字段；
- 产品不承诺任意上游或本地代理实际支持 WebSocket。

### 5.6 TOML 双向同步

**CDEX-FR-016** 两个开关必须从实际供应商 TOML 解析，不得仅依赖独立布尔字段。

**CDEX-FR-017** 用户操作开关时，应对当前 TOML 草稿进行非破坏式结构化补丁；用户手工编辑 TOML 后，开关、冲突和兼容状态应同步更新。

**CDEX-FR-018** TOML 修改必须保留：

- 注释；
- 其他表；
- 字段顺序；
- 空行和大部分原有排版；
- 其他请求头；
- 与本功能无关的字段。

不得通过整体解析后重新序列化的方式格式化整个文件。

整份 TOML 无法解析时，两个开关仍可见但全部禁用并显示解析错误，不得重建或覆盖配置。单个受管字段异常只影响诊断，不得阻止其他字段保存或另一个能力开关的补丁。

### 5.7 官方延迟生成、保存警告与代理投影

**CDEX-FR-018A** 固定官方供应商缺少显式 Provider 表时，两个能力默认关闭，打开或普通保存表单不得注入任何 Provider 表。首次实际开启任一能力时才生成 `model_provider = "custom"` 和最小 `[model_providers.custom]`，包含 `name = "OpenAI"`、`requires_openai_auth = true`、`wire_api = "responses"` 及用户开启的能力。使用私有 Provider meta 记录骨架所有权；两个能力都关闭时，仅当骨架仍完全符合受管形状且没有用户字段时删除。显式 Provider 表优先于统一会话历史注入。

**CDEX-FR-018B** 仅在添加或编辑成功且最终 Provider 明确启用 WebSocket 时计算警告。模型来源为顶层 `model`、`review_model` 和 `modelCatalog.models[].model`；忽略空值，取最后一个 `/` 后的片段，大小写不敏感地以 `gpt-` 开头才视为 GPT 系列。任一可识别非 GPT 模型产生模型风险；无可识别模型不产生该风险。Codex 代理接管开启时产生代理链路风险。

**CDEX-FR-018C** 后端通过可选结构化警告码返回风险，前端本地化并合并为一条 warning toast，替换普通成功 toast。添加前缀为“供应商已添加”，编辑前缀为“供应商已保存”；风险持续存在时每次成功保存都提示。保存失败只显示错误，供应商切换不提示，不持久化确认状态。

**CDEX-FR-018D** 普通代理投影继续改写路由所需的 `base_url` 和 `wire_api`，但保留显式 WebSocket 和受管生图请求头；官方代理投影从供应商配置复制这两个能力，不再固定写入 `supports_websockets = false`。关闭接管后应从保存的 Provider/可信备份恢复能力。当前本地代理仅实现 HTTP/SSE，不实现 WebSocket Upgrade，提示不得表述为已支持。

### 5.8 live 配置变化判定

**CDEX-FR-019** 是否询问重启必须由本次操作是否真实改变用户级 live Codex 配置决定，而不是由按钮名称或供应商数据库是否修改决定。

可能触发的操作包括：

- 添加首个且立即成为当前供应商；
- 编辑当前供应商；
- 切换当前供应商；
- 删除当前供应商并导致 live 配置切换或清理；
- 导入或恢复后改变 live 配置；
- 修改两个新开关；
- 其他实际改变 `~/.codex/config.toml` 的操作。

仅修改非当前供应商数据库记录且 live 内容未变时不得弹框。

**CDEX-FR-020** 同一用户操作最多弹出一次重启询问。

### 5.9 Codex 重启询问

**CDEX-FR-021** 当 live 配置已变且可信 Codex 桌面应用正在运行时，显示模态框：

- 标题：配置已更新；
- 说明：重启后新配置生效；
- 主操作：重启 Codex；
- 次操作：稍后手动重启。

不提供“以后不再询问”。

**CDEX-FR-022** Codex 未运行时，不显示重启模态框，只显示配置保存成功。

**CDEX-FR-023** 用户选择稍后重启时，配置保持已保存状态，不回滚。

### 5.10 可信重启流程

**CDEX-FR-024** 只允许管理项目现有可信安装检测所识别的 Codex 桌面应用：

- Windows 使用已验证包身份、安装记录及其所属进程；
- macOS 使用 Bundle ID 和已验证 Bundle 路径；
- 不按模糊进程名匹配；
- 不处理 Codex CLI、终端任务或 IDE 插件。

**CDEX-FR-025** 若存在多个无法唯一选择的安装或运行实例，不自动关闭；提示配置已保存并要求手动重启。

**CDEX-FR-026** 用户确认后：

1. 请求正常退出；
2. 等待最多 8 秒；
3. 仍未退出时进行第二次确认；
4. 用户确认后才强制终止；
5. 确认旧实例退出；
6. 使用可信安装记录启动；
7. 最多等待 15 秒确认可信新进程出现；
8. 只有确认后提示“Codex 已重启”。

**CDEX-FR-027** 正常退出失败且用户拒绝强制终止时，取消启动步骤；配置仍保存成功。

**CDEX-FR-028** 启动或确认失败时，不回滚有效配置；错误提示应区分“配置已保存”和“重启失败”。

## 6. WorkBuddy 功能需求

### 6.1 顶层导航

**WB-FR-001** 顶层应用顺序为：

```text
Claude Code
Claude Desktop
Codex
WorkBuddy
Gemini
Grok Build
OpenCode
OpenClaw
Hermes
```

**WB-FR-002** WorkBuddy 默认显示，并可在现有“应用显示设置”中隐藏或恢复。

**WB-FR-003** WorkBuddy 页面使用本地打包图标，不允许运行时远程加载图标。

### 6.2 独立页面

**WB-FR-004** WorkBuddy 是独立单页，只显示：

- 配置文件路径、存在状态、模型数量；
- URL；
- API Key；
- “允许无 API Key”；
- 获取模型；
- 自动获取模型列表；
- 全选、取消全选；
- 手动模型多行输入；
- 保存配置。

不得显示供应商列表、当前供应商、MCP、Skills、Prompt、Profile、Session 或用量入口。

**WB-FR-005** 进入页面时不回填现有 URL、API Key 或模型；不得把 WorkBuddy 明文 API Key 复制到应用数据库、设置或日志。页面只展示路径、存在状态和模型总数。

### 6.3 API Key

**WB-FR-006** API Key 默认必填。“允许无 API Key”默认关闭。

**WB-FR-007** 未勾选允许无 Key 且 Key 为空时：

- 禁止获取模型；
- 禁止保存；
- 显示字段级错误。

**WB-FR-008** 勾选允许无 Key 后：

- 允许获取模型和保存；
- 获取模型不发送 `Authorization`；
- 新模型写入 `"apiKey": ""`。

**WB-FR-009** 对已有同 ID 模型，Key 输入为空且允许无 Key 时，默认保留每个旧条目的原 Key。若至少一个目标条目已有非空 Key，显示额外确认项“同时清空目标模型已有的 API Key”；只有勾选后才写空。

### 6.4 URL 规范化

**WB-FR-010** 只接受绝对 `http://` 或 `https://` URL。

**WB-FR-011** 允许本机、局域网和内网 HTTP。对非回环地址的 HTTP 显示明文传输警告，但不阻止保存。

**WB-FR-012** 拒绝：

- URL 内嵌用户名或密码；
- query string；
- fragment；
- 非 HTTP(S) scheme；
- 无 host 的 URL。

**WB-FR-013** 规范化顺序：

1. 去除首尾空白；
2. 解析 URL；
3. 去除多余尾部 `/`；
4. 若路径以 `/models`、`/chat/completions` 或 `/responses` 结尾，剥离该标准接口后缀；
5. 若剩余路径存在一个完整、区分大小写的 `v1` 路径段，不再追加；
6. 否则在现有路径后追加 `/v1`；
7. 保存规范化后的基础 URL；
8. 获取模型只请求 `<normalized-base-url>/models`。

示例：

| 输入 | 保存 URL | 获取模型 URL |
|---|---|---|
| `https://api.example.com` | `https://api.example.com/v1` | `https://api.example.com/v1/models` |
| `https://api.example.com/v1/` | `https://api.example.com/v1` | `https://api.example.com/v1/models` |
| `https://gateway.example.com/openai` | `https://gateway.example.com/openai/v1` | `https://gateway.example.com/openai/v1/models` |
| `https://gateway.example.com/openai/v1/chat/completions` | `https://gateway.example.com/openai/v1` | `https://gateway.example.com/openai/v1/models` |
| `https://example.com/v1/proxy` | `https://example.com/v1/proxy` | `https://example.com/v1/proxy/models` |

### 6.5 自动获取模型

**WB-FR-014** 使用单一确定地址，不自动回退到其他路径。

**WB-FR-015** 请求策略：

- 方法：GET；
- 总超时：15 秒；
- 响应体上限：2 MiB；
- 最多 3 次重定向；
- 只允许同源重定向；
- 禁止 HTTPS 降级到 HTTP；
- 跨源重定向失败；
- 不忽略无效 TLS 证书；
- 继承 FyAgent 显式全局代理；未设置时遵循系统代理；
- API Key 只对原始源和经验证的同源重定向发送。

**WB-FR-016** 只接受标准响应：

```json
{
  "data": [
    { "id": "model-a" }
  ]
}
```

允许条目包含其他字段，但必须存在非空字符串 `data[].id`。不兼容时提示改用手动输入。

**WB-FR-017** 最多接收 1000 个去重后的模型 ID；按上游响应顺序保留，不排序。模型 ID 去重区分大小写，保留首次出现。

**WB-FR-018** 获取成功后默认全选；用户可自由勾选、取消单个模型，并可使用“全选”“取消全选”。

### 6.6 手动模型与最终顺序

**WB-FR-019** 手动模型按换行分隔；逐行去除首尾空白，忽略空行。

**WB-FR-020** 最终目标序列：

1. 自动获取结果按响应顺序；
2. 仅保留用户勾选项；
3. 手动模型按行序追加；
4. 完全相同 ID 去重，保留第一次；
5. 不按字母排序。

至少需要一个目标模型才能保存。

### 6.7 模型写入规则

**WB-FR-021** 只管理 `~/.workbuddy/models.json`。目录或文件不存在时自动创建；不读取或写入 `.codebuddy`，不使用项目级配置。

**WB-FR-022** 根节点必须是 JSON 数组；解析失败或根节点不是数组时拒绝覆盖。

**WB-FR-023** 新模型使用固定规则：

```json
{
  "id": "<模型 ID>",
  "name": "<模型 ID>",
  "vendor": "Custom",
  "url": "<规范化 URL>",
  "apiKey": "<API Key 或空字符串>",
  "supportsToolCall": true,
  "supportsImages": true,
  "supportsReasoning": true,
  "useCustomProtocol": false,
  "reasoning": {
    "defaultEffort": "max",
    "supportedEfforts": ["low", "medium", "high", "xhigh", "max"],
    "canDisableThinking": false
  }
}
```

**WB-FR-024** 更新同 ID 模型时覆盖上述受管字段，保留未知字段和原数组位置；删除 `onlyReasoning`，不写 `onlyReasoning: false`，以字段缺失表示“仅思考模式关闭”。

**WB-FR-025** 不同 ID 的旧模型保持原内容和顺序；新模型按最终目标序列追加到数组末尾。

### 6.8 重复 ID 冲突

**WB-FR-026** 保存前扫描现有数组。若本次目标 ID 在旧文件中出现多次，默认拒绝写入并列出重复 ID 和出现次数。

**WB-FR-027** 冲突模态框提供“取消”和“覆盖重复条目”：

- 选择取消：不写主文件、不写备份；
- 选择覆盖：更新该 ID 的所有重复条目的受管字段；
- 每个重复条目的未知字段和数组位置分别保留；
- 不删除、不合并重复条目；
- 非空新 Key 覆盖所有重复条目；
- 空 Key 遵循已有 Key 防误清空规则。

界面必须说明“覆盖不会自动去重，重复条目仍将保留”。

### 6.9 保存、备份与反馈

**WB-FR-028** 保存前重新读取文件并验证，以避免使用页面初始快照覆盖外部变化。检测到并发变化时要求用户刷新后重试。

**WB-FR-029** 文件存在且合法时，成功修改前保留固定单份备份：

```text
~/.workbuddy/models.json.backup
```

每次成功保存覆盖上一份备份；备份始终表示最近一次成功修改前的完整文件。首次创建无旧文件时不创建空备份。

**WB-FR-030** 主文件和备份均使用同目录临时文件、刷盘和平台原子替换；失败不得留下半写 JSON。

**WB-FR-031** 保存成功后只显示“配置已保存”，不询问或控制 WorkBuddy 重启。WorkBuddy 官方更新日志已声明 `models.json` 支持热更新；本功能不承诺或检测旧版本行为。

## 7. 非功能要求

### 7.1 安全

- API Key 不写日志、错误、遥测、应用数据库或设置；
- 错误响应摘要必须脱敏；
- 跨源重定向不得携带 Authorization；
- 备份文件按凭据文件保护；
- Unix 主文件、备份和临时文件目标权限为 `0600`；
- Windows 依赖用户主目录 ACL 且不得扩大访问范围；
- Codex 强制终止必须有二次确认；
- 不使用模糊进程名杀进程。

### 7.2 可靠性

- TOML 无损编辑；
- JSON 未知字段保留；
- 文件写入具备冲突检测、备份和原子替换；
- 失败不回滚已经成功写入的有效 Codex 配置；
- 用户可明确区分配置保存结果和应用重启结果。

### 7.3 性能

- WorkBuddy 页面加载只读取一次状态和文件摘要，不解析或显示密钥；
- 模型响应最多 2 MiB / 1000 ID；
- TOML 分析应针对单个表单草稿，不扫描无关文件；
- 进程状态等待不得阻塞 UI 线程。

### 7.4 可访问性与本地化

- 开关、按钮、冲突、警告、模态框具有可访问名称和键盘操作；
- 支持现有四套语言资源：简体中文、繁体中文、英语、日语；
- 密钥输入默认掩码，支持现有密码显示交互模式；
- 全选和取消全选状态应对屏幕阅读器可感知。

## 8. 外部依据

- OpenAI 官方配置参考说明 `model_providers.<id>.http_headers` 是静态请求头，`supports_websockets` 表示 Responses API WebSocket transport；供应商配置属于用户级 `config.toml`。
- WorkBuddy 官方资料说明自定义模型包含 URL、API Key、工具调用、图片输入、推理能力，自定义协议关闭时使用标准 `/chat/completions` 并自动补全。
- WorkBuddy 官方更新日志说明 5.1.1 已支持 `models.json` 配置热更新。
- WorkBuddy JSON 精确字段以项目方提供的真实配置样例为目标 Schema，不宣称是官方公开 JSON Schema。
