# 04 — 验收标准与测试场景

## 1. 验收方法

每个场景均定义前置、操作和可观察结果。验收可以通过 UI、最终配置文件、结构化命令结果和平台进程状态完成。测试场景用于判定需求是否满足，不是开发任务清单。

## 2. 总体通过条件

- P0 场景全部通过；
- 不发生用户配置、注释、未知字段或 API Key 的非预期丢失；
- 不发生按模糊名称终止进程；
- 不把 WorkBuddy 加入 Provider/MCP/Skills 等后端业务域；
- Windows/macOS 的 Codex 重启流程符合平台矩阵；
- WorkBuddy 配置写入在 Windows/macOS/Linux 符合路径、备份和权限要求；
- 四种现有界面语言无缺失键或回退占位符；
- 文档中的非目标功能未被隐式实现为强依赖。

### CDEX-A03 内置第三方 API 预设

- 前置：类型名不是 `custom`，但具有第三方 base URL、普通 Key 和可编辑 provider 表。
- 期望：按能力显示两个开关。

### CDEX-A04 历史供应商延迟迁移—保持默认开启

- **P0**
- 前置：历史适用供应商无目标头、无迁移元数据。
- 打开编辑：显示“待迁移”且开关开启，但未落盘。
- 取消：数据库和 live 配置不变。
- 再打开并保存：写入目标头，元数据设为 true。

### CDEX-A05 历史供应商延迟迁移—用户明确关闭

- **P0**
- 前置同 A04。
- 操作：关闭开关并保存。
- 期望：不写目标头；元数据为 true；再次打开显示关闭，不重新默认开启。

### CDEX-A06 已有受管头

- **P0**
- 前置：目标请求头使用不同大小写，值为 `local-image-extension`。
- 期望：开关显示开启；保存不创建重复键；其他头不变。

### CDEX-A07 同名冲突头

- **P0**
- 前置：`X-OpenAI-Actor-Authorization = "another-extension"`。
- 期望：显示冲突；不覆盖、不删除、不新增另一键；无法通过开关绕过；保存其他字段不改变冲突值。

### CDEX-A08 多个大小写变体

- **P0**
- 前置：TOML 同时存在两个语义同名键。
- 期望：视为冲突；不自动归一化。

### CDEX-A09 保留其他请求头

- **P0**
- 前置：已有 `X-Company-ID`、`User-Agent`。
- 开关开/关。
- 期望：只增删受管键，其他键和值完全保留。

### CDEX-A10 注释与格式保留

- **P0**
- 前置：Provider 表包含注释、空行、非标准字段顺序和内联表。
- 操作：切换两个开关。
- 期望：除目标 Item 外，注释、顺序和空行不被整体重排；TOML 可解析。

### CDEX-A11 WebSocket 开启

- **P0**
- 前置：Responses 格式。
- 操作：开启并保存。
- 期望：`supports_websockets = true` 位于目标 Provider 表。

### CDEX-A12 WebSocket 关闭

- **P0**
- 操作：关闭并保存。
- 期望：字段被删除，不写 false。

### CDEX-A13 切换到非 Responses

- **P0**
- 前置：WebSocket 已开启。
- 操作：切换为 Chat Completions/Anthropic。
- 期望：草稿自动关闭并移除字段，显示说明；保存后无字段。

### CDEX-A14 手工绕过协议限制

- **P0**
- 前置：非 Responses 格式。
- 操作：TOML 编辑器手工加入 `supports_websockets=true`。
- 期望：保存被阻止，错误明确指出只支持 Responses。

### CDEX-A15 TOML 结构错误

- **P0**
- 前置：`http_headers` 不是字符串映射或 TOML 无法解析。
- 期望：显示诊断，不静默重写，不保存损坏配置。

## 7. WorkBuddy URL 场景

### WB-URL02 已有 `/v1`

### WB-URL03 自定义路径

### WB-URL04 标准完整端点

- **P0**
- 输入 `/v1/chat/completions`、`/v1/models`、`/v1/responses`。

### WB-URL05 `v1` 中间段

### WB-URL06 非匹配文本

### WB-URL07 非法凭据和参数

### WB-URL08 HTTP 警告

## 11. 文件可靠性场景

### WB-S01 单份备份

- **P0**
- 第一次修改已有文件后 backup 等于修改前主文件；第二次修改后 backup 被覆盖为第二次修改前版本；无时间戳历史文件。

### WB-S02 原子替换失败

- **P0**
- 模拟写入/替换失败。
- 期望主文件保持旧合法内容，不出现零字节或半 JSON；错误明确。

### WB-S03 备份失败

- **P0**
- backup 无法创建/替换。
- 期望不修改主文件。

### WB-S04 并发变化

- **P0**
- 页面加载后外部修改主文件。
- 保存返回并发冲突，不覆盖；刷新后可重试。

### WB-S05 进程内并发保存

- **P1**
- 两个保存请求并发。
- 期望串行化，其中至少一个基于 revision 明确失败或在新 revision 上安全处理，不丢更新。

### WB-S06 Unix 权限

- **P0 / macOS/Linux**
- 主、backup、临时目标最终权限为当前用户可读写，不向组/其他用户开放。

### WB-S07 Windows ACL

- **P0 / Windows**
- 文件位于用户 profile；不新增宽泛 ACL；原子替换不产生无保护的中间窗口。

### WB-S08 热更新反馈

- **P1**
- 保存后只显示成功，不弹 WorkBuddy 重启、不启动或探测 WorkBuddy。

## 14. 验收证据

建议每次验收保留以下非敏感证据：

- 受管字段前后 TOML diff，敏感值脱敏；
- 注释保留示例；
- Provider mutation 的 `liveConfigChanged`；
- 重启阶段和可信身份摘要；
- WorkBuddy JSON fixture 前后 diff，使用假 Key；
- backup 与修改前文件哈希一致性；
- URL 规范化输入/输出；
- HTTP mock 的重定向、大小和超时结果；
- 四语言截图或自动化可访问性结果。

不得把真实 API Key、完整用户配置或私有服务响应纳入测试产物。
