# 03 — 配置数据模型与安全设计

## 1. 目标

本设计处理两类敏感配置：

1. Codex 用户级 `config.toml`，可能包含供应商地址、认证引用、请求头和用户注释；
2. WorkBuddy `models.json`，可能直接包含明文 API Key。

核心目标是最小修改、可回退、避免凭据泄漏、避免并发覆盖，并为未来未知字段保留空间。

## 2. Codex 配置模型

### 2.1 目标位置

Codex 供应商配置写入用户级配置：

```text
~/.codex/config.toml
```

项目现有 live 配置路径解析继续作为唯一来源，需兼容 `CODEX_HOME` 等已有逻辑。不得把 `model_providers` 写到项目 `.codex/config.toml`。

### 2.2 目标 TOML

```toml
model_provider = "custom"

[model_providers.custom]
name = "Example"
base_url = "https://api.example.com/v1"
wire_api = "responses"
supports_websockets = true
http_headers = {
  "x-openai-actor-authorization" = "local-image-extension",
  "X-Company-ID" = "team-a"
}
```

字段语义：

| 字段 | 所有权 | 默认 | 关闭语义 |
|---|---|---|---|
| `http_headers["x-openai-actor-authorization"]` | 本功能管理特定键 | 新供应商开启 | 删除匹配且值为受管值的键 |
| `supports_websockets` | 本功能管理字段 | 关闭 | 删除字段 |
| 其他 `http_headers` | 用户/其他功能 | 不修改 | 不修改 |
| 其他 Provider 字段 | 用户/现有功能 | 不修改 | 不修改 |

### 2.3 头名称冲突

HTTP 字段名语义大小写不敏感，而 TOML 字符串键可区分大小写。必须进行语义扫描：

```text
lower_ascii(key) == "x-openai-actor-authorization"
```

状态：

| 现状 | 状态 | 允许自动开启 | 允许自动关闭 |
|---|---|---:|---:|
| 无同名键 | off / legacyPending | 是 | 幂等 |
| 一个同名键，值为受管值 | on | 幂等 | 是 |
| 一个同名键，值不同 | conflict | 否 | 否 |
| 多个语义同名键 | conflict，除非可证明完全同值且可安全归一化；本设计仍按冲突处理 | 否 | 否 |
| `http_headers` 不是字符串映射 | invalid | 否 | 否 |

不自动归一化大小写，避免破坏用户或代理对原始格式的依赖。

### 2.4 延迟迁移元数据

Provider 数据库元数据：

```json
{
  "imageExtensionConfigured": true
}
```

该字段不写入 Codex TOML。状态真值表：

| 元数据 | 受管头 | 冲突 | UI |
|---|---|---|---|
| 缺失 | 缺失 | 否 | 历史待迁移，默认开启草稿 |
| `true` | 缺失 | 否 | 明确关闭 |
| 任意 | 存在受管值 | 否 | 开启 |
| 任意 | 任意 | 是 | 冲突 |

元数据只用于歧义消解，不能覆盖实际 TOML。

### 2.5 无损 TOML 操作

使用 `toml_edit` 的 `DocumentMut`、`Item`、`TableLike` 和装饰信息：

- 定位 `[model_providers.<id>]`；
- 修改目标 Item；
- 保持前后缀、注释和表顺序；
- 不重建整个文档；
- 补丁前后再次解析；
- 若结构不符合预期，返回诊断而非猜测。

开关补丁先作用于表单草稿。Provider 保存和 live 同步继续走现有安全写入链路。

## 3. WorkBuddy JSON Schema

### 3.1 目标文件

```text
Windows: %USERPROFILE%\.workbuddy\models.json
macOS/Linux: ~/.workbuddy/models.json
Backup: ~/.workbuddy/models.json.backup
```

只使用当前用户主目录，不读取项目目录，不回退 `.codebuddy`。

### 3.2 根结构

```json
[
  { "id": "model-a", "...": "..." }
]
```

根节点不是数组即失败。数组元素若不是对象或缺少可识别的字符串 ID：

- 不应静默删除；
- 为保证按 ID upsert 的确定性，保存应安全失败并报告元素索引；
- 用户修复后重试。

### 3.3 Rust 领域模型

建议使用 `serde_json::Map` 保留未知字段：

```rust
#[derive(Serialize, Deserialize, Clone)]
#[serde(rename_all = "camelCase")]
struct WorkBuddyModel {
    id: String,
    name: Option<String>,
    vendor: Option<String>,
    url: Option<String>,
    api_key: Option<String>,
    supports_tool_call: Option<bool>,
    supports_images: Option<bool>,
    supports_reasoning: Option<bool>,
    use_custom_protocol: Option<bool>,
    reasoning: Option<WorkBuddyReasoning>,
    #[serde(default, flatten)]
    extra: serde_json::Map<String, serde_json::Value>,
}

#[derive(Serialize, Deserialize, Clone)]
#[serde(rename_all = "camelCase")]
struct WorkBuddyReasoning {
    default_effort: Option<String>,
    supported_efforts: Option<Vec<String>>,
    can_disable_thinking: Option<bool>,
    #[serde(default, flatten)]
    extra: serde_json::Map<String, serde_json::Value>,
}
```

`onlyReasoning` 可显式建模为可选字段或从 `extra` 删除；序列化时不写回。

### 3.4 受管字段

保存目标模型时强制设置：

```json
{
  "id": "<id>",
  "name": "<id>",
  "vendor": "Custom",
  "url": "<normalized URL>",
  "apiKey": "<规则决定>",
  "supportsToolCall": true,
  "supportsImages": true,
  "supportsReasoning": true,
  "useCustomProtocol": false,
  "reasoning": {
    "defaultEffort": "max",
    "supportedEfforts": ["low", "medium", "high", "xhigh", "max"],
    "canDisableThinking": false
  }
}
```

更新 `reasoning` 时，建议保留其内部未知字段，再覆盖三个受管子字段。删除顶层 `onlyReasoning`。

### 3.5 API Key 决策表

| 条目 | 输入 Key | 允许无 Key | 清空旧 Key | 结果 |
|---|---|---:|---:|---|
| 新模型 | 非空 | 任意 | 任意 | 写入输入值 |
| 新模型 | 空 | 否 | 任意 | 校验失败 |
| 新模型 | 空 | 是 | 任意 | 写空字符串 |
| 旧模型 | 非空 | 任意 | 任意 | 覆盖旧值 |
| 旧模型 | 空 | 否 | 任意 | 校验失败 |
| 旧模型 | 空 | 是 | 否 | 每个旧条目保留自身 Key |
| 旧模型 | 空 | 是 | 是 | 写空字符串 |

前端的“清空旧 Key”只在有实际旧非空 Key 时出现；最终判定由后端重新读取文件后执行。

### 3.6 重复 ID

重复检测按字符串精确、区分大小写。假设目标 `model-a` 在旧数组出现 3 次：

- 默认返回冲突，不生成备份；
- 用户确认覆盖后，3 个条目均更新受管字段；
- 每个条目自己的 `extra` 和原位置保留；
- 不创建第 4 个条目；
- 不删除其中任何一个；
- 返回 `updatedEntries = 3`、`duplicateIds = [{id,count}]`，供成功提示或审计，但 UI 仍只需“配置已保存”。

## 4. URL 规范化

### 4.1 解析规则

使用 Rust `url::Url`，不使用字符串 contains 判断域名或 query 中的 `v1`。

```text
Input
  -> trim
  -> parse absolute URL
  -> validate scheme/host/userinfo/query/fragment
  -> normalize terminal slash
  -> strip known endpoint suffix
  -> inspect decoded path segments for exact "v1"
  -> append v1 if absent
  -> derive models URL by appending models
```

### 4.2 后缀剥离

只剥离路径末尾：

- `/models`
- `/chat/completions`
- `/responses`

先去尾斜杠，再匹配完整段序列。路径大小写按 URL 语义保留，只有小写标准形式被识别。

### 4.3 `v1` 判定

- 仅路径段精确等于 `v1`；
- `v10`、`api-v1`、域名 `v1.example.com` 不匹配；
- `https://example.com/openai/v1/proxy` 已有 `v1`，不追加；
- 无 `v1` 时在现有路径末尾追加。

### 4.4 安全校验

| 条件 | 行为 |
|---|---|
| HTTPS | 允许 |
| HTTP loopback | 允许 |
| HTTP 非 loopback | 允许但警告 |
| 用户名/密码 | 拒绝 |
| query | 拒绝 |
| fragment | 拒绝 |
| file/ftp/ws 等 scheme | 拒绝 |
| IPv6 / IDN | 由 URL 库规范化；显示时避免混淆，日志用安全形式 |

允许内网是明确产品要求，因此不做传统 SSRF 网段阻断；安全边界转为用户确认、重定向限制、TLS 和凭据保护。

## 5. 模型获取安全

### 5.1 代理

短生命周期 HTTP 客户端继承：

1. FyAgent 显式全局代理；
2. 未配置时系统代理；
3. 现有项目定义的直连语义。

只复用代理策略，不复用可能具有宽松重定向或长期 Cookie 状态的全局 client。

### 5.2 同源定义

同源键：

```text
(lowercase scheme, canonical host, effective port)
```

重定向要求新 URL 与原始 URL 同源，且不允许 `https -> http`。即使 host 相同，端口变化也视为跨源。

### 5.3 Authorization

- Key 非空时发送 `Authorization: Bearer <key>`；
- Key 为空且显式允许时不创建该 header；
- 每次重定向前由 policy 验证同源；
- 跨源直接终止，不依赖 HTTP 库是否自动剥离 header；
- 请求/错误日志只记录脱敏 URL 和状态。

### 5.4 响应限制

- 总超时 15 秒；
- 若 `Content-Length > 2 MiB`，读取前拒绝；
- 未知长度时流式累计，超过即中止；
- 错误响应摘要设置较小上限，例如 4 KiB，并去除控制字符；
- JSON 解析只接受对象根和 `data` 数组；
- ID 必须是非空字符串；
- 最多 1000 个唯一 ID；
- 保留响应顺序。

## 6. 文件事务与备份

### 6.1 Revision

`get_workbuddy_status` 返回当前文件字节的 SHA-256 或等价不透明 revision。保存请求携带该 revision。

保存时：

1. 获取进程内写锁；
2. 重新读取当前文件；
3. 比较 revision；
4. 不一致则返回 `ConcurrentModification`；
5. 一致后解析、冲突检测、生成新内容；
6. 再执行备份和替换。

revision 不包含 API Key 内容，不能反推文件；前端只把它作为不透明字符串。

### 6.2 备份事务

文件存在且本次写入已经通过全部校验后：

1. 将旧主文件字节写到 `models.json.backup.tmp.*`；
2. `flush + sync_all`；
3. 原子替换 `models.json.backup`；
4. 将新 JSON 写到 `models.json.tmp.*`；
5. `flush + sync_all`；
6. 原子替换主文件；
7. 必要时同步父目录；
8. 清理临时文件。

主文件替换失败时，旧主文件保持；备份可能已经更新为同一旧内容，仍满足“最近修改前版本”。

### 6.3 平台原子替换

- Unix：同文件系统 `rename` 替换，并设置 `0600`；
- Windows：使用 `ReplaceFileW` 或具备替换语义的 `MoveFileExW`，不得先删除目标再 rename；
- 临时文件必须与目标在同一目录；
- 首次创建使用创建后原子 rename；
- 不能直接复用当前 Windows `atomic_write` 的“删除后重命名”路径。

### 6.4 权限

- Unix：主文件、备份、临时文件创建为 `0600`；目录遵循用户主目录策略；
- Windows：保持用户 profile 目录继承 ACL，不授予 Everyone/Users 额外权限；
- 复制旧文件权限时不能把过宽权限扩散到新凭据文件；新文件以最小权限为目标。

## 7. JSON 格式化

输出建议：

- UTF-8；
- 2 空格缩进；
- 文件末尾换行；
- 数组顺序按规则保持；
- 对象受管字段采用稳定顺序，未知字段跟随原反序列化映射能力；
- 不要求字节级保留旧 JSON 排版，要求语义、未知字段和顺序保留。

与 Codex TOML 不同，用户已选择 WorkBuddy JSON 安全写入和字段保留，没有要求保留注释；JSON 本身无标准注释。

## 8. 凭据生命周期

### 8.1 前端

- API Key 只保存在 React 组件状态；
- 不写 localStorage/sessionStorage/query cache 持久化；
- 不进入 URL、路由、analytics 或错误对象；
- 页面卸载后清空；
- 不自动从 `models.json` 回填；
- 密码框默认隐藏。

### 8.2 IPC

- Key 通过 Tauri invoke 参数传输；
- command 参数 Debug 日志不得打印完整结构；
- 错误类型不得包含请求对象；
- 可在后端构造 `SecretString`/显式 redaction wrapper，避免误格式化。

### 8.3 文件

- API Key 按 WorkBuddy 目标格式明文保存在本地，这是产品协议约束；
- 备份同样含 Key，按同等级保护；
- 文档和测试 fixture 必须使用假 Key；
- 日志和 crash report 不附带配置正文。

## 9. Codex 重启安全

### 9.1 身份验证

不得接受前端传入任意 PID。后端从可信安装记录推导运行实例：

- Windows：包身份、可执行路径、签名/现有验证结果；
- macOS：Bundle ID、Bundle URL、可执行 URL；
- 多实例必须属于同一唯一可信安装，否则歧义失败。

### 9.2 强制终止

- 正常退出先行；
- 8 秒后才请求强制确认；
- token 绑定检测时的实例集合并设置短期过期；
- 继续强制前再次验证实例仍对应同一可信身份；
- 不终止新出现且未绑定的进程；
- 记录阶段，不记录用户配置。

### 9.3 启动确认

- 启动命令成功不等于重启成功；
- 15 秒内确认可信新实例；
- 可使用启动时间/旧 PID 集合区分新实例；
- macOS 可结合 `isFinishedLaunching`；
- 失败时返回可操作错误，配置不回滚。

## 10. 错误模型

建议统一机器可判定代码：

```text
WORKBUDDY_INVALID_URL
WORKBUDDY_API_KEY_REQUIRED
WORKBUDDY_FETCH_HTTP_ERROR
WORKBUDDY_FETCH_REDIRECT_REJECTED
WORKBUDDY_FETCH_RESPONSE_TOO_LARGE
WORKBUDDY_FETCH_INVALID_SCHEMA
WORKBUDDY_CONFIG_INVALID_JSON
WORKBUDDY_CONFIG_ROOT_NOT_ARRAY
WORKBUDDY_CONFIG_DUPLICATE_TARGET
WORKBUDDY_CONFIG_CONCURRENT_MODIFICATION
WORKBUDDY_CONFIG_BACKUP_FAILED
WORKBUDDY_CONFIG_WRITE_FAILED
CODEX_FEATURE_HEADER_CONFLICT
CODEX_FEATURE_INCOMPATIBLE_WEBSOCKET
CODEX_DESKTOP_AMBIGUOUS
CODEX_DESKTOP_FORCE_CONFIRMATION_REQUIRED
CODEX_DESKTOP_QUIT_FAILED

```

用户消息本地化；底层错误详情可折叠展示，但必须脱敏。

## 11. 资料依据

- WorkBuddy 官方资料明确 API Key 仅在本地配置文件保存；本设计因此把主文件和备份都视为凭据文件。
- WorkBuddy 官方说明关闭自定义协议时使用标准路径并自动补全；本项目保存规范化 `/v1` 基础 URL且固定 `useCustomProtocol=false`。
- RFC 9110 对认证保护空间和同源凭据风险有明确讨论；本设计采用更严格的同源重定向策略。
- WorkBuddy 精确 `reasoning` 字段和值来自项目方提供的真实配置样例，而非公开官方 Schema。

资料链接见 `README.md`。
