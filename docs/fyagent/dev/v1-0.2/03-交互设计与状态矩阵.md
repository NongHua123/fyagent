# 03 — 交互设计与状态矩阵

## 1. 交互设计原则

1. 用户看到的是“现在发生了什么、下一步能做什么”，不是进程和安装技术细节；
2. 配置保存结果与后续动作结果分开表达；
3. 加载、后台刷新、失败和业务不可用必须是不同状态；
4. 搜索输入立即生效，选择状态不因过滤而丢失；
5. 破坏性操作必须明确提示风险，但同一操作不重复确认；
6. 关键操作位置稳定，页面切换和滚动条变化不得造成大范围跳动；
7. 所有动态状态通过文本和可访问属性表达，不只依赖图标或颜色。

## 2. WorkBuddy 页面信息架构

### 2.1 页面结构

窄窗口：

```text
┌────────────────────────────────────┐
│ WorkBuddy 标题与说明               │
├────────────────────────────────────┤
│ 配置状态                           │
│ [下载 WorkBuddy ↗]                 │
├────────────────────────────────────┤
│ 已有模型 ID                        │
├────────────────────────────────────┤
│ 连接配置                           │
├────────────────────────────────────┤
│ 远程模型                           │
└────────────────────────────────────┘
```

宽窗口：

```text
┌──────────────────┬─────────────────┐
│ 配置状态         │ 已有模型 ID     │
│ 下载入口         │ 即时搜索        │
├──────────────────┴─────────────────┤
│ 连接配置                           │
├────────────────────────────────────┤
│ 远程模型                           │
└────────────────────────────────────┘
```

规则：

- 页面内容使用标准全宽壳层；
- 双列断点应根据卡片最小可用宽度确定，不硬编码为“只要屏幕宽就双列”；
- Base URL、API Key 和远程模型区域始终占整行；
- 卡片内部可限制输入控件最大可读宽度，但不得重新限制整个页面为居中窄栏。

### 2.2 配置状态卡片

标题栏：

```text
配置状态                               [下载 WorkBuddy ↗]
```

状态内容继续显示现有非敏感信息，例如配置路径、是否存在、唯一模型数量和备份状态。

下载按钮：

- 文案：`下载 WorkBuddy`
- 图标：`ExternalLink`
- 样式：现有 `Button`，`variant="outline"`
- Tooltip/辅助说明：`将在默认浏览器中打开 WorkBuddy 官网`
- 目标：`https://www.workbuddy.cn/`
- 状态查询加载、失败或文件不存在时仍可用；
- 调用期间禁用，避免重复触发；
- 成功不显示 Toast；
- 失败显示：`无法打开 WorkBuddy 官网，请检查系统默认浏览器设置。`

### 2.3 已有模型 ID 卡片

标题和计数：

```text
已有模型（12）                         [刷新]
```

计数只统计静默去重后的唯一 ID。

内容顺序：

1. 搜索输入；
2. 只读 ID 列表；
3. 空状态或错误状态。

搜索：

- Placeholder：`搜索已有模型 ID`
- 输入即过滤；
- 无搜索按钮；
- 清空按钮可复用现有 Input 附件样式；
- 不区分大小写；
- 只匹配 ID。

列表：

- 每个 ID 一行；
- 不显示 Checkbox、编辑、删除、重复次数、URL 或 Key 状态；
- 按第一次出现顺序；
- 超过最大高度后在卡片内部滚动。

状态矩阵：

| 状态 | 展示 |
|---|---|
| 首次读取 | 骨架或 `正在读取已有模型` |
| 文件不存在/模型为空 | `暂无已配置模型` |
| 有数据 | 显示唯一 ID 列表 |
| 搜索无结果 | `没有匹配的模型 ID` |
| 配置格式错误 | 简短错误：`无法读取现有模型配置，请检查 models.json。`，保留刷新按钮 |
| 手动刷新 | 保留旧列表并在刷新按钮显示旋转，不清空列表 |
| 刷新失败且有旧列表 | 保留列表，显示非阻塞错误提示 |

### 2.4 连接配置卡片

字段顺序：

1. Base URL；
2. API Key；
3. `允许无 API Key`；
4. 条件式 `保存时清空已有模型的 API Key`；
5. `获取模型`。

API Key 行为：

- 继续使用密码输入框和显示/隐藏能力；
- 获取或保存后不清空；
- 离开 WorkBuddy 页面后清空；
- 不提供“从配置读取 Key”功能；
- 不在错误描述中回显 Key。

清空选项：

- 默认关闭；
- 只有 API Key 输入为空，且当前选择包含已有模型时显示或启用；
- 文案：`保存时清空已有模型的 API Key`；
- 辅助说明：`未选择时，空输入会保留已有 API Key。`

### 2.5 远程模型卡片

卡片头部：

```text
远程模型                         已选择 18 / 当前结果 20
```

工具栏：

```text
[搜索模型 ID、名称或 Vendor] [全选当前结果] [取消选择当前结果]
```

规则：

- 模型获取成功后全部默认选中；
- 已有 ID 仍选中并可操作；
- 已有 ID 可显示简短 `已存在` 标签；
- 搜索隐藏项保留选择；
- 全选/取消只作用于当前过滤结果；
- 无搜索词时“当前结果”即完整结果；
- 搜索不发后端请求，不显示“搜索”按钮；
- 1000 条以内使用简单内存过滤，不引入防抖造成输入延迟。

建议行结构：

```text
☑ model-id                                  已存在
```

不强行展示远程接口未可靠提供的能力信息。

## 3. WorkBuddy 保存与覆盖流程

### 3.1 无已有模型冲突

```text
用户点击保存
→ 后端按最新 revision 校验
→ 原子写入
→ 刷新配置状态和已有模型 ID
→ 保留 API Key 输入
→ 显示保存成功
```

### 3.2 存在已有模型

第一次提交返回已有 ID 集合，不写文件。前端打开一次汇总对话框。

对话框建议：

- 标题：`覆盖已有模型？`
- 正文：`以下模型已经存在。继续后将更新这些模型的连接地址和 API Key。配置文件中所有同 ID 条目都会一并更新。`
- 列表：唯一模型 ID；不显示重复次数；
- 次要按钮：`取消`
- 主要按钮：`继续保存`

用户确认后：

- 使用第一次提交的不可变请求快照；
- 带覆盖能力令牌或显式 `overwriteExisting=true` 再提交；
- 后端重新验证 revision 和覆盖集合；
- 新增与覆盖一次原子完成；
- 成功后刷新状态和 ID，Key 保持；
- 取消不写文件，也不清空表单。

### 3.3 并发修改

当用户确认期间外部程序修改 `models.json`：

- 当前事务失败关闭；
- 对话框关闭；
- 自动刷新已有模型；
- 显示：`配置已被其他程序修改，请检查后重新保存。`
- 不自动重新提交；
- API Key、Base URL 和模型选择保持不变。

## 4. Codex 重启交互

### 4.1 不弹框的情况

| 状态 | 行为 |
|---|---|
| live 配置未变化 | 保持原保存反馈，不检查桌面运行状态 |
| Codex 未运行 | 配置保存成功，不启动、不弹重启框 |
| 当前平台不支持自动重启 | 显示人工重启说明对话框或非破坏性提示，不提供强制按钮 |
| 无精确 PFN/Bundle ID | 不执行进程操作，只允许手动重启 |

### 4.2 强制关闭并重启询问框

同一对话框根据内部原因使用一句简单说明，不展示技术细节。

建议通用结构：

- 标题：`需要重启 Codex`
- 说明首句：`配置已保存。`
- 原因句按状态选择：
  - 多运行实例：`检测到多个正在运行的 Codex。`
  - 多安装：`检测到多个可用的 Codex 安装。`
  - 实例无法唯一绑定：`当前无法确认唯一的 Codex 实例。`
- 风险句：`继续后将强制关闭所有匹配的 Codex。未保存的工作可能丢失，随后只会启动一个实例。`
- 次要按钮：`稍后手动重启`
- 主要按钮：`强制关闭并重启`

交互约束：

- 默认焦点在次要按钮；
- 风险图标和破坏性按钮样式复用现有 Dialog/Button；
- 操作开始后两个按钮禁用；
- 禁用 Esc、遮罩关闭和重复点击；
- 对话框保持打开并显示进行状态；
- 取消只关闭对话框，不回滚配置、不额外 Toast。

### 4.3 执行状态

用户只需看到简短过程文本：

```text
正在重启 Codex…
```

内部可以有 `detect`、`force_quit`、`launch`、`verify` 阶段，但不逐项展示给普通用户。

### 4.4 成功

- 关闭对话框；
- 显示成功 Toast：`Codex 已重启，新配置已生效。`

### 4.5 失败

失败结果对话框固定为：

```text
Codex 重启未完成

配置已保存，但 Codex 重启未完成。

[我将手动重启] [再次尝试重启]
```

不得显示：

- 发现/关闭/失败数量；
- PID、包族名、Bundle ID；
- 自动选择的版本或安装范围；
- 阶段名称或原始系统错误。

`再次尝试重启`：

- 直接重新枚举并执行；
- 不回到风险确认；
- 按钮进入忙碌状态；
- 仍失败时保持相同对话框。

`我将手动重启`：

- 关闭对话框；
- 不追加 Toast；
- 配置保持已保存。

## 5. Codex 版本显示状态矩阵

### 5.1 字段级状态

推荐两个独立的判别联合：

```ts
type LocalVersionState =
  | { kind: "loading" }
  | { kind: "installed"; version: string }
  | { kind: "not_installed" }
  | { kind: "error" };

type RemoteVersionState =
  | { kind: "loading" }
  | { kind: "available"; version: string }
  | { kind: "refreshing"; version: string }
  | { kind: "refetch_error"; version: string }
  | { kind: "initial_network_error" }
  | { kind: "platform_unavailable" }
  | { kind: "metadata_error" };
```

### 5.2 用户可见矩阵

| 场景 | 本地版本值 | 最新版本值 | 状态区 | 安装/更新 | 启动 |
|---|---|---|---|---|---|
| 首次本地检测 | `正在检测本地版本` + spinner | 按远程自身状态 | `正在检查桌面应用状态` | 禁用 | 取决于已知本地状态；通常禁用 |
| 首次远程获取 | 按本地状态 | `正在获取最新版本号` + spinner | `正在检查桌面应用状态` | 禁用 | 已确认安装时可用 |
| 正常可用 | 版本或未安装 | 版本 | 正常状态 | 按版本差决定 | 已安装可用 |
| 后台刷新 | 保留本地 | 保留版本 + spinner | `正在刷新最新版本` | 禁用 | 可用 |
| 后台刷新失败且有数据 | 保留本地 | 保留版本 | `获取最新版本失败，请检查网络是否正常` | 禁用 | 可用 |
| 首次网络失败 | 保留本地 | `获取失败` | 简短网络错误 + 重试 | 禁用 | 已安装可用 |
| 平台无发布 | 保留本地 | `当前平台暂无可用版本` | 平台说明 | 不提供 | 已安装可用 |
| 元数据异常 | 保留本地 | `版本信息异常` | 版本信息错误 + 重试/详情 | 禁用 | 已安装可用 |

### 5.3 可访问性

- 使用已有单一 `aria-live="polite"` 状态区公告变化；
- 版本值中的旋转图标 `aria-hidden="true"`；
- 文本本身表达加载和错误；
- 刷新按钮包含 `aria-label`；
- 不让多个动态区域同时重复朗读同一状态。

## 6. 顶部栏最终交互

### 6.1 正常工作区

```text
[品牌] [P1] [P2/更多] [      AppSwitcher      ] [+]
```

- `+` 固定最右；
- AppSwitcher 紧邻主操作槽；
- 当前九个应用直接可见；
- P2 可以已经位于顶部 More；
- AppSwitcher 的右边缘不受 P1/P2 出现或消失影响。

### 6.2 WorkBuddy

```text
[品牌] [空/必要上下文] [P2/更多] [AppSwitcher] [空槽]
```

空槽与 `+` 占位完全一致，使 AppSwitcher 右边缘保持稳定。

### 6.3 受限工作区

```text
[品牌] [P1紧凑] [TopMore] [当前应用 + AppMore] [+]
```

规则：

1. P2 进入 TopMore；
2. Profile 文本缩短；
3. 非当前应用进入 AppMore；
4. 极端情况下 Profile 只显示图标；
5. `+`、当前应用和两个 More 中必要的那个始终可见；
6. 不产生横向滚动；
7. 不弹“屏幕太小”Toast。

### 6.4 键盘顺序

建议顺序与视觉顺序一致：

```text
P1 → TopMore → 可见应用 → AppMore → +
```

WorkBuddy 空槽不进入 Tab。More 菜单中保留原应用/操作的可访问名称和选中状态。

## 7. WorkBuddy 页面滚动

- 主页面滚动容器负责卡片之间的垂直滚动；
- 已有模型和远程模型列表只有达到最大高度后才内部滚动；
- 鼠标滚轮位于列表内时优先滚动列表，到边界后自然传递给页面；
- 卡片内不得出现横向滚动；长 ID 使用可选择文本和省略显示，Tooltip 可显示完整 ID；
- `scrollbar-gutter: stable` 只作为宽度稳定补强，不替代顶部栏结构修复。

## 8. Windows 用户可见行为

### 8.1 启动

- 用户启动正式版；
- Windows 原生 UAC 请求管理员权限；
- 批准后显示 FyAgent；
- 拒绝后本次启动结束；
- 不额外显示 FyAgent 自定义授权说明。

### 8.2 重复启动

- FyAgent 已在托盘中时再次点击快捷方式，仍可能出现 UAC；
- 批准后只激活已有窗口；
- 不出现第二个可见窗口；
- 用户取消 UAC 时没有变化。

### 8.3 深链接

- 浏览器打开 `fyagent://` 可能触发 UAC；
- 批准后进入现有导入确认；
- 取消后本次导入终止；
- 含 API Key 的链接继续允许，但 Key 必须默认遮罩，且不进入日志。

### 8.4 管理员状态

设置或关于页显示：

```text
运行权限：管理员
Windows 版本需要管理员权限以支持 Codex 一键安装等功能。
```

不在顶部栏增加徽标，不在每次启动显示 Toast。

### 8.5 开机自启与托盘

- Windows 设置页隐藏或禁用开机自启，并说明当前管理员启动模式下不支持；
- “关闭时最小化到托盘”继续默认开启；
- 用户主动关闭该设置后，关闭窗口即退出；
- 开启时可增加简短说明：`关闭窗口后，FyAgent 将继续以管理员权限在后台运行。`

## 10. 禁止的交互回归

- 加载期间显示“暂不可用”或“未安装”；
- WorkBuddy 保存后清空 API Key；
- 搜索需要点击按钮才生效；
- 搜索后全选修改不可见的全部模型；
- 已有模型自动隐藏或禁用；
- WorkBuddy 顶部显示禁用的 `+`；
- 通过增加透明元素让不可见按钮仍可点击；
- Codex 重启失败只显示短暂 Toast；
- 在普通用户界面显示 PID、PFN、Bundle ID、路径或候选数量；
- 受限工作区直接裁剪关键操作；
- 外链成功后额外显示冗余成功 Toast。
