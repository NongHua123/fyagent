# 01 — 需求规格与决策基线

## 1. 文档目的

本文定义本次修复与增强的产品要求、边界、验收语义和已确认取舍。需求编号是后续设计、代码、测试和验收的追踪主键。

## 2. 背景与目标

当前版本已具备 Codex 桌面安装/启动、Codex live 配置变化后的重启协调器、WorkBuddy 模型配置页、顶层应用切换器和多平台桌面壳层，但存在以下用户可感知问题：

1. Codex 运行目标不唯一时，只显示“请手动重启”的信息 Toast，用户无法直接作出强制重启决策；
2. WorkBuddy 无法查看已有模型 ID，保存后清空 API Key，远程模型不能即时搜索；
3. WorkBuddy 页面使用居中最大宽度，产生大面积空白；切换 WorkBuddy 时顶部栏大幅位移；
4. 顶部栏宽度不足时，最右侧 `+` 会被裁剪；
5. 远程版本仍在获取时错误显示“暂不可用”；本地版本仍在检测时可能提前显示“未安装”；
6. Windows 普通双击不主动请求管理员权限，部分用户环境下 Codex 一键安装不可用；
7. 全程管理员运行会扩大子进程和 WebView 命令面的权限，需要补齐边界。

目标是在不改造为完整 WorkBuddy 管理器、不增加第二套 UI 基础组件、不引入 Windows 启动器的前提下，提供可实施、可回归、可审计的工程方案。

## 3. 范围

### 3.1 包含

- Codex 多安装、多实例和身份绑定不唯一时的强制重启询问；
- Codex 强制关闭、单次启动、失败重试和竞态处理；
- WorkBuddy 已有模型 ID 读取、展示、搜索和刷新；
- WorkBuddy 双根 JSON 兼容、覆盖确认、`availableModels` 维护和 API Key 生命周期；
- WorkBuddy 官网入口；
- WorkBuddy 页面壳层、顶部栏、AppSwitcher、`+` 主操作槽和窗口尺寸恢复；
- Codex 本地/远程版本的加载、刷新和错误状态；
- Windows UAC、安装范围、代码签名、自定义安装路径、外部进程权限、单实例、外链、深链接和 IPC 安全；
- 四种现有语言；
- Rust、React、桌面 E2E、几何和视觉回归测试。

### 3.2 非目标

- 不实现 WorkBuddy 模型删除、拖拽排序、逐项编辑或完整模型管理；
- 不安装、检测、升级、启动、关闭或重启 WorkBuddy；
- 不自动合并或删除历史重复模型条目；
- 不把 WorkBuddy 加入 Provider、MCP、Skills、Prompt、Profile、用量或代理切换业务域；
- 不控制 ChatGPT Classic；
- 不按模糊进程名、窗口标题或显示名称关闭任何进程；
- 不新增 Windows 非提权启动器或深链接中继 EXE；
- 不实现 Windows 全用户 Codex 部署；
- 不为局域网代理增加访问令牌；
- 不禁止深链接携带明文 API Key；
- 不把 CI 改为 PR 或主分支自动触发；
- 不在本次文档中设计特定自动化开发框架的角色、提示词或工作流。

## 4. 用户与平台前置条件

### 4.1 Codex 用户

- 使用的是原 Codex 应用更新后的新 ChatGPT 桌面应用；
- 不包括 ChatGPT Classic；
- Windows 或 macOS 上至少能通过精确应用标识识别目标；
- 用户理解强制关闭可能导致未保存工作丢失。

### 4.2 WorkBuddy 用户

- 不要求 WorkBuddy 已安装；
- 用户对 `~/.workbuddy/models.json` 有读写权限；
- 上游端点提供 OpenAI-compatible 模型列表；
- 用户自行承担第三方端点的费用、隐私和合规责任。

### 4.3 Windows 用户

- 正式支持的登录账户本身属于本地 Administrators 组；
- 若 UAC 使用另一个管理员账户凭据导致安全上下文切换，应用必须在读取用户数据前阻止启动；
- 正式安装包具备可信 Authenticode 签名。

## 5. Codex 强制重启需求

### 5.1 产品身份

**CR-001 [已确认决策]** 目标应用为“Codex 桌面应用（更新后显示为 ChatGPT）”。不得控制 ChatGPT Classic、Codex CLI、IDE 插件、终端任务或名称相似程序。

**CR-002 [已确认决策]** Windows 仅以精确 Package Family Name 作为运行候选的最低应用级标识；macOS 仅以精确 Bundle Identifier 作为最低应用级标识。不得退化为进程名、窗口标题或显示名称匹配。

**CR-003 [工程设计]** 连精确 PFN/Bundle Identifier 都无法取得时，内部状态应为 `untrusted_target`。该状态只允许手动重启，不得强制终止进程。

### 5.2 询问触发

**CR-004** 只有后端确认一次用户操作真实改变当前生效的 Codex live 配置时，才检查运行状态并考虑重启。

**CR-005** 同一用户操作最多显示一次重启询问。

**CR-006** Codex 未运行时，不显示重启询问，也不得自动启动；只保留原配置保存成功反馈。

**CR-007 [已确认决策]** 以下状态不得只作为信息 Toast：

- 多个可信安装候选；
- 多个精确匹配的运行实例；
- 应用级身份可确认、但实例级身份无法唯一绑定。

上述状态均进入决策对话框，并允许用户选择强制关闭并重启。

### 5.3 强制操作

**CR-008 [已确认决策]** 用户确认后直接执行强制关闭，不先尝试正常退出，也不显示第二次强制确认。

**CR-009** 执行时重新枚举当前存在的全部精确匹配实例，不使用弹窗出现时的过期 PID 列表；新出现的匹配实例也属于本次关闭范围。

**CR-010** 对同一应用的多个窗口，应先按进程身份去重，避免对同一进程重复终止。

**CR-011 [已确认决策]** 强制关闭所有候选安装下精确匹配的全部 Codex 实例，确认全部退出后只启动一次。

**CR-012** 若确认时已无运行实例，仍验证自动选择的安装并启动一次。

**CR-013 [已确认决策]** 多个安装候选使用固定自动优先级：

1. 当前有运行实例的安装；
2. 版本较新；
3. 系统级安装；
4. 当前用户安装；
5. 稳定标识按固定顺序排序。

不得使用平台枚举顺序作为业务优先级。

**CR-014** 用户确认到实际执行之间候选集合变化时，重新计算同一固定优先级并继续；用户界面不展示内部选择过程。

**CR-015** 启动前必须重新验证所选安装仍存在且可启动。验证失败时不得先关闭实例。

**CR-016 [已确认决策]** 任一匹配实例关闭失败时，不启动新实例。

**CR-017** 成功条件为：全部目标实例退出，所选安装启动一次，并在规定时间内检测到新的精确匹配运行实例。

### 5.4 用户反馈

**CR-018** 初始对话框必须：

- 明确配置已保存；
- 明确将强制关闭所有匹配的 Codex；
- 提示未保存工作可能丢失；
- 默认焦点在“稍后手动重启”；
- 执行期间禁止重复提交、Esc 关闭和遮罩关闭；
- 取消不回滚已保存配置。

**CR-019 [已确认决策]** 重启失败使用结果对话框，而不是 Toast：

- 标题：`Codex 重启未完成`
- 正文：`配置已保存，但 Codex 重启未完成。`
- 次要按钮：`我将手动重启`
- 主要按钮：`再次尝试重启`

用户界面不显示实例数量、PID、路径、错误阶段、候选版本或内部标识。

**CR-020** 点击“再次尝试重启”后直接重新枚举并执行，不重复显示风险确认；点击“我将手动重启”只关闭对话框，不追加 Toast。

## 6. WorkBuddy 需求

### 6.1 配置兼容

**WB-001 [已确认决策]** 同时支持以下根结构：

```json
[
  { "id": "model-a" }
]
```

```json
{
  "models": [
    { "id": "model-a" }
  ]
}
```

**WB-002** 写回时保持原根结构。文件不存在时新建对象根 `{ "models": [...] }`。

**WB-003** 保留对象根的未知顶层字段、模型条目的未知字段、原有模型顺序和 JSON 键顺序。

**WB-004** 对象根的 `models` 缺失时视为空数组；`models` 存在但不是数组、数组条目不是对象或 ID 为空时，禁止覆盖原文件。

### 6.2 已有模型 ID

**WB-005 [已确认决策]** 页面只展示当前配置中已经存在的模型 ID，不展示名称、Vendor、URL、能力、API Key 状态或重复数量。

**WB-006** 同一 ID 在页面中静默去重，按配置中第一次出现的顺序显示，计数使用唯一 ID 数量。

**WB-007** 已有模型使用独立只读卡片：进入页面自动读取、保存成功后自动刷新、提供手动刷新和即时搜索。

**WB-008** 已有模型搜索仅匹配 ID，大小写不敏感，输入变化立即生效，无搜索按钮。

### 6.3 远程模型与选择

**WB-009** 模型获取成功后，所有远程模型默认选中，包括已经存在的 ID。

**WB-010** 已有 ID 在远程结果中保持可见和可选择，可使用简短 `已存在` 标记，但不得禁用。

**WB-011** 远程搜索对 ID、可用名称和 Vendor 做大小写不敏感的子串匹配；纯前端过滤，不新增后端请求，不要求防抖。

**WB-012** 搜索隐藏的模型保持原选择状态；“全选/取消选择”只作用于当前过滤结果。

**WB-013** ID 在写入前去除首尾空白，唯一性与覆盖比较保持大小写敏感的精确匹配。

### 6.4 覆盖事务

**WB-014 [已确认决策]** 任一目标 ID 已存在时，先返回全部唯一覆盖目标，不写文件；前端只弹出一次汇总确认。

**WB-015** 混合提交的新模型和已有模型必须在确认后作为一个原子事务完成，不允许先保存新模型再询问覆盖。

**WB-016** 确认期间配置 revision 变化时，中止写入、刷新已有 ID，并要求重新发起保存；不得基于旧快照继续覆盖。

**WB-017 [已确认决策]** 覆盖已有条目时只更新：

- `url`
- `apiKey`

不得改写 `name`、`vendor`、能力字段、推理设置、Token 限制或未知字段。

**WB-018 [已确认决策]** 历史上同一 ID 有多个条目时，更新全部精确匹配条目，不合并、不删除；确认框只说明“所有同 ID 条目都会更新”，不显示数量。

### 6.5 API Key

**WB-019** 非空 API Key 覆盖所有匹配已有条目的 Key；空 Key 默认保留每个条目原有 Key；只有用户明确选择清空时才写入空值。

**WB-020** 创建新模型时，若“允许无 API Key”开启，可写入空 Key。

**WB-021 [已确认决策]** API Key 在当前 WorkBuddy 页面组件内存中保留：获取成功、保存成功、保存失败或覆盖冲突后均不清空；离开 WorkBuddy 页面或关闭窗口时清空。

**WB-022** API Key 不得写入 FyAgent 数据库、设置、查询缓存或普通日志，也不得从 `models.json` 读取并回填到表单。

### 6.6 `availableModels`

**WB-023 [已确认决策]** 对对象根按以下规则维护：

- 字段不存在：保持不存在；
- 空数组：保持为空；
- 非空数组：按本次保存顺序追加目标 ID，已有值不重复、不删除、不重排；
- 新文件默认不创建该字段。

根数组格式无此字段，不做隐式迁移。

### 6.7 官网入口

**WB-024** 配置状态卡片标题栏右侧显示 `下载 WorkBuddy`，所有平台始终显示并打开固定地址 `https://www.workbuddy.cn/`。

**WB-025** 点击后直接调用系统默认浏览器，不二次确认；调用期间临时禁用；成功不显示 Toast；失败文案固定为：

> `无法打开 WorkBuddy 官网，请检查系统默认浏览器设置。`

状态加载、状态失败或配置文件不存在时，该按钮仍可使用。

## 7. Codex 版本状态需求

**CV-001** 本地版本首次检测完成前显示 `正在检测本地版本`，不得提前显示“未安装”。

**CV-002** 远程版本首次请求完成前显示 `正在获取最新版本号`，不得显示“暂不可用”。

**CV-003** 自动重试期间继续显示加载文案，只有最终失败后才进入错误状态。

**CV-004** 已有远程版本时后台刷新：保留版本号、显示旋转状态，并显示 `正在刷新最新版本`。

**CV-005** 后台刷新期间禁用安装和更新；已安装应用的启动功能仍可用。

**CV-006 [已确认决策]** 后台刷新失败且有旧版本数据时：继续显示版本号，不显示“上次成功获取”“缓存”或“旧数据”等标记；状态固定为：

> `获取最新版本失败，请检查网络是否正常`

提供重试，禁用安装和更新，启动仍可用。

**CV-007** 无缓存且网络请求最终失败时，版本值显示 `获取失败`。

**CV-008** 当前平台或架构无发布包时显示 `当前平台暂无可用版本`。

**CV-009** 发布元数据格式或校验异常时显示 `版本信息异常`。

**CV-010** 视图模型必须使用显式判别联合状态，不允许继续通过 `version === undefined` 推断加载或错误原因。

## 8. WorkBuddy 页面与顶部栏需求

### 8.1 页面壳层

**UI-001** 删除 WorkBuddy 页面根级 `mx-auto max-w-4xl`，复用 Provider 页面标准左右间距和滚动壳层。

**UI-002** 小窗口所有卡片单列；宽窗口仅“配置状态”和“已有模型”两卡双列，连接配置和远程模型占整行。

**UI-003** 页面只有一个主纵向滚动区；已有模型和远程模型使用有界 `ScrollArea`；不得出现页面级横向滚动。

**UI-004** 主滚动容器使用稳定滚动条占位，防止滚动条出现或消失造成横向跳动。

### 8.2 顶部栏结构

**UI-005 [已确认决策]** 顶层应用页面顶部栏顺序固定为：

```text
品牌/导航 → P1 控件 → P2/顶部更多 → 弹性 AppSwitcher → 固定最右主操作槽
```

**UI-006** Provider 顶层页面主操作槽显示 `+`；WorkBuddy 不显示 `+`，但保留与按钮及间距完全同宽的空槽。

**UI-007** WorkBuddy 空槽不得显示轮廓、接收点击、进入 Tab、显示 Tooltip；必须对辅助技术隐藏。

**UI-008** `+` 必须是业务顶部栏最右侧操作，不得进入 More，不得被 `overflow` 裁剪，不得通过透明或宽度归零隐藏。

**UI-009** Provider 与 WorkBuddy 切换前后：AppSwitcher 右边缘和主操作槽右边缘变化均不得超过 `1 CSS px`。

### 8.3 优先级与收纳

**UI-010** P0 始终可见：`+`/空槽、当前激活应用、AppSwitcher More。

**UI-011** P1 尽量直接可见：Proxy、Failover、ProfileSwitcher、Claude Desktop Route Toggle。

**UI-012** P2 可进入顶部 More：Skills、Prompts、Sessions、MCP、Workspace、Env、Tools、Agents、Memory、Web UI 等快捷入口。

**UI-013** 正常目标最小宽度下，当前九个应用入口和 P0/P1 直接可见；P2 可收纳。

**UI-014** 受限工作区按以下顺序降级：P2 收纳；Profile 名称截断；非当前应用进入 AppSwitcher More；必要时 Profile 退化为图标。P0 不得丢失。

### 8.4 窗口尺寸和状态

**UI-015** 产品目标最小宽度由自动化最大组合夹具测量：四种语言、九个应用、P1 全开、Profile 最大显示文本；测量值增加至少 32 CSS px 并向上取 8 的倍数。

**UI-016** 目标宽度作为版本化常量提交，不在每次启动时根据瞬时 DOM 动态改变产品基线。

**UI-017** 默认宽度为目标最小宽度加 64–96 CSS px 舒适余量，默认高度 700 CSS px，最终尺寸不超过当前工作区约 90%。

**UI-018** 当前工作区小于目标宽度时，适配或最大化窗口、降低有效最小宽度并进入受限模式；不显示 Toast。

**UI-019** 主窗口在隐藏阶段执行受控状态恢复：钳制非法尺寸和位置、恢复离屏窗口、最后恢复最大化；合法用户尺寸保持不变。

**UI-020** 显示器、DPI、分辨率或工作区变化时，短时间合并事件后重新计算有效最小宽度；回到大工作区后恢复产品最小值，但不无条件放大合法窗口。

## 9. Windows 管理员与发布需求

### 9.1 启动和账户

**WIN-001 [已确认决策]** Windows 正式主程序嵌入 `requestedExecutionLevel=requireAdministrator`，`uiAccess=false`，并保留 Common Controls v6。

**WIN-002** 本地开发、Rust 单元测试、Vitest 和自动桌面 E2E 使用普通权限测试构建；正式候选包单独验证提升清单。

**WIN-003** 不增加非提权启动器。用户拒绝 UAC 时 FyAgent 不启动，也不显示自定义应用提示。

**WIN-004** 仅正式支持当前登录账户本身属于本地 Administrators 组；进程用户与交互用户不一致时，在读取 FyAgent 用户数据前阻塞退出。

**WIN-005** 设置页或关于页显示 `运行权限：管理员`；主标题栏不增加管理员徽标。正式发布版若未提升，显示阻塞错误。

### 9.2 安装与签名

**WIN-006** FyAgent 使用 per-machine 安装，默认目录 `%ProgramFiles%\FyAgent`。

**WIN-007** 允许用户选择其他本地固定磁盘目录，但必须拒绝普通用户可写目录、用户目录、桌面、下载、临时目录、UNC、网络共享、移动磁盘和重解析点逃逸。

**WIN-008** 程序目录 ACL 必须保证普通用户只读/执行，管理员与 SYSTEM 可修改；用户配置、数据库和凭据继续位于用户数据目录。

**WIN-009** 当前测试阶段检测到旧 per-user 版本时阻止安装，提示用户手动卸载；不实现自动迁移，卸载不得删除用户数据。

**WIN-010** 停止发布 Windows Portable 绿色版。

**WIN-011** Windows 正式 EXE、MSI及必要安装产物必须使用受信任 Authenticode 证书和时间戳；签名验证失败不得发布。

**WIN-012** Codex 继续只为当前 Windows 用户部署，不改为所有用户安装。

### 9.3 自启、托盘和单实例

**WIN-013** Windows 隐藏并禁用开机自启，升级时清理旧启动项；macOS/Linux 保持现有行为。

**WIN-014 [已确认决策]** Windows 继续默认“关闭时最小化到托盘”，用户可在设置中关闭；界面说明其会让管理员进程继续在后台运行。

**WIN-015** 只允许一个业务实例。第二个激活进程必须在 WebView、数据库、托盘、代理和业务服务初始化前完成转发并退出。

**WIN-016** 重复点击快捷方式或触发深链接仍可能先出现 UAC；该行为不视为创建第二个业务实例。

### 9.4 子进程和外链权限

**WIN-017** 外部用户应用默认以当前交互用户普通权限启动；无法获得普通令牌时失败，不得静默回退到管理员权限。

**WIN-018** 浏览器、文件管理器、终端、编辑器、WorkBuddy 和 Codex 桌面应用使用统一的普通用户启动抽象。

**WIN-019 [已确认决策]** Claude、Gemini、Grok、OpenCode、OpenClaw 等 CLI 的安装和升级是明确的管理员权限白名单例外。

**WIN-020** Windows 所有 HTTP/HTTPS 外链通过普通权限 Explorer 进程打开；不得通过 `cmd.exe` 或 PowerShell 拼接命令。

### 9.5 深链接、代理和 IPC

**WIN-021 [已确认决策]** 保留 `fyagent://`；Windows 每次协议激活均可能出现 UAC，取消后本次导入终止。

**WIN-022 [已接受风险]** 深链接继续允许携带明文 API Key，但必须限制 URL 长度、字段数量、编码层级和字段大小，并在应用内二次确认；日志不得记录完整 URL 或凭据。

**WIN-023** 深链接不得直接触发 Codex 安装、强制进程终止、计划任务、程序目录写入或其他管理员/破坏性命令。

**WIN-024 [已接受风险]** 代理继续允许非回环/局域网监听，不新增访问令牌；现有行为必须明确记录为安全取舍。

**WIN-025** 对全部 IPC 命令按只读、用户数据写入、敏感凭据、外部进程、管理员和破坏性操作分类。

**WIN-026** 管理员和破坏性命令必须在后端复验参数和调用状态；前端隐藏按钮不构成授权。

**WIN-027** 强制终止、配置覆盖等操作使用短期、一次性、不透明能力令牌；令牌不得包含 PID、路径或凭据。

**WIN-028** 收紧 Tauri Capability、CSP、URL/path/process allowlist；未使用命令不得继续暴露。

**WIN-029** 普通日志不得记录 API Key、访问令牌、完整深链接、PID、完整私有路径或管理员账户标识。

## 10. 组件复用与本地化

**NFR-001** 优先复用现有 UI 原语，不新增同类 Button、Checkbox、Dialog、Popover 或 ScrollArea。

**NFR-002** 抽取即时过滤、过滤结果全选/取消、隐藏项保留选择等行为；不要创建充满条件参数的通用万能列表组件。

**NFR-003** 简体中文、繁体中文、英语和日语必须同步新增所有文案；本地化完整性测试禁止缺失键被英语回退掩盖。

**NFR-004** 用户可见信息保持简单；复杂诊断只进入脱敏日志和测试证据。

**NFR-005** API Key 和短期能力令牌不得进入持久化前端状态、查询缓存或可复制错误文本。
