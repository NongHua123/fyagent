# 07 — 验收标准与自动化测试计划

## 1. 验收目标

测试体系必须同时验证：

1. 数据不丢失、事务不部分成功；
2. 进程操作只作用于精确目标；
3. 用户看到的状态、文案和操作简单准确；
4. 顶部栏和页面在多尺寸、多语言、多平台下不裁剪、不跳动；
5. Windows 正式产物的权限、签名、安装和子进程行为符合设计；
6. 测试证据可追踪且不泄露凭据。

## 2. 总体通过条件

- P0 场景全部通过；
- Rust、TypeScript 类型检查、格式检查和现有单元测试无回归；
- 四种语言无缺失键或非预期 fallback；
- 关键几何断言和视觉基线全部通过；
- 正式 Windows 包的嵌入清单、签名和安装模式验证通过；
- 测试日志中不存在固定测试 API Key、能力令牌、完整深链接或私有路径；
- CI 仍为手动触发；
- Windows 发布目录不存在 Portable ZIP。

## 3. 测试层次

### 3.1 Rust 单元与服务测试

覆盖：

- WorkBuddy 文档解析、覆盖事务、revision、备份和原子写；
- Codex 安装比较器、候选集合、能力令牌和重启状态机；
- Windows 路径安全、用户身份、命令分类和日志脱敏；
- 窗口尺寸钳制纯函数。

### 3.2 React/Vitest 测试

覆盖：

- WorkBuddy Key 生命周期、搜索、选择、覆盖确认和状态卡片；
- 版本字段状态映射和按钮可用性；
- Codex 重启协调器对话框状态和简洁文案；
- 顶部栏 descriptor、主操作槽和 More 语义；
- 四语言键完整性。

### 3.3 桌面 E2E

使用 WebdriverIO 与 Tauri 桌面测试服务，覆盖真实 WebView 布局、窗口尺寸、键盘导航和 IPC 交互。管理员/破坏性后端使用测试替身，不对用户机器真实进程和配置执行操作。

### 3.4 视觉回归

- 关键区域像素基线：阻塞；
- 整窗截图：整体布局证据；
- 平台、缩放和语言基线分离；
- 普通测试禁止自动更新基线；
- 显式更新基线时先通过几何和交互断言，再执行自动语义检查；
- 正式验收命令只读，不修改代码或基线。

### 3.5 正式候选系统验证

Windows UAC 安全桌面不能由普通 WebDriver 可靠操作。正式候选包通过：

- 静态提取清单；
- Authenticode 验证；
- per-machine 安装测试；
- 受控 Windows 虚拟机中的系统冒烟。

该系统冒烟不是人工视觉审批，主要验证操作系统权限和安装行为。

## 4. 建议命令

实际脚本名可按项目约定调整，建议目标：

```text
pnpm typecheck
pnpm format:check
pnpm test:unit
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
pnpm test:e2e
pnpm test:e2e:visual
pnpm test:e2e:visual:update     # 显式、受控
pnpm test:i18n
pnpm test:windows-release      # Windows Runner/VM
```

`test:e2e:visual` 发现缺失基线时必须失败，不得自动把实际截图保存为正式基线。

### WIN-T14 深链接

- **P0**
- 每次可能 UAC；
- 长度/schema/动作限制；
- 用户确认前不写；
- Prompt 正文完整可滚动审阅，超过 500 字符的尾部不得被省略；
- Provider 的 `enabled=true` 明确显示立即切换/写入 live 配置请求和警示，但默认不激活；只有独立用户批准才可切换，`false` 或缺失明确显示不自动切换；
- 明文测试 Key 不进入日志；
- 不可直接调用管理员/破坏性命令。

### WIN-T15 IPC 授权

- **P0**
- 直接从前端调用强制终止、覆盖、ACL 等命令但无有效能力令牌；
- 期望全部拒绝；
- 前端隐藏状态不影响后端结果。

## 14. 视觉回归设计

### 14.1 严格基线区域

- Provider 顶部栏：正常、受限；
- WorkBuddy 顶部栏和空主操作槽；
- WorkBuddy 状态/下载、已有 IDs、远程搜索和覆盖对话框；
- Codex 版本卡：首次加载、刷新、刷新失败、无缓存错误、平台无版本、元数据异常；
- Codex 重启确认和失败对话框。

### 14.2 整窗证据

每个关键场景另存整窗截图，用于检查：

- 大面积白边；
- 页面比例；
- 顶部栏与内容区平衡；
- 弹窗相对位置；
- 受限模式整体可用性。

整窗截图不必全部作为像素硬门禁，避免系统装饰和抗锯齿噪声扩大基线量。

### 14.3 稳定化

每个场景：

1. 禁用动画和 transition；
2. 固定光标、时间、时区、随机数；
3. 模拟所有远程请求；
4. 等待字体和图标完成；
5. 等待 Query 和布局稳定；
6. 连续采集两次截图和几何 JSON；
7. 两次在阈值内一致才执行基线比较；
8. 不稳定重试一次，仍不稳定则基础设施失败。

### 14.4 平台隔离

Windows、macOS、Linux 分别维护基线；Windows 100/125/150% 分目录。不得用 Linux 截图作为 Windows 基线。

### 14.5 Git LFS

正式基线路径：

```text
tests/e2e/visual-baselines/**/*.png
```

使用 Git LFS。临时候选、实际图、差异图和日志不提交普通 Git，作为工作流制品或本地任务证据。

## 15. 自动化开发代理的使用边界

- 可在本地/交互式开发阶段运行应用、读取截图和几何结果、修改 UI 并最多进行两轮修复—重测；
- 普通 CI 不依赖在线代理、账号或模型服务；
- 普通测试中语义意见不覆盖确定性断言；
- 更新正式视觉基线时，自动语义检查必须通过；
- 正式验收命令只读，不允许自动修改源码或基线；
- 两轮仍未收敛的问题必须在结果中如实记录，不得宣称“未发现视觉问题”。

不在本文规定具体代理产品、角色名称或工作流实现。

## 16. 证据产物

每次桌面 E2E 生成：

```text
layout-metrics.json
interaction-results.json
visual-review.json（如执行语义检查）
actual/
baseline/
diff/
full-window/
frontend.log
backend.log
test-report/
```

脱敏要求：

- API Key 替换为固定测试占位；
- 不包含真实用户路径；
- 不包含 PID、SID、能力令牌；
- 深链接只保存去查询参数摘要；
- 成功运行至少保存摘要和关键截图；失败保存完整证据。

## 17. 手动 CI 行为

`.github/workflows/ci.yml` 继续：

```yaml
on:
  workflow_dispatch:
```

可新增输入选择：

```text
unit
rust
windows-release
visual-windows
visual-macos
visual-linux
all
```

但不得添加 `pull_request` 或 `push` 自动触发。发布工作流可以继续由发布行为触发，但发布前所有 Windows 签名/清单门禁必须强制执行。

## 18. 验收报告要求

最终验收报告至少包含：

- 源码版本/包哈希；
- 需求编号到测试编号映射；
- 各平台/缩放/语言结果；
- Windows 签名与清单摘要；
- 视觉基线版本；
- 未解决警告与已接受风险；
- 证据制品路径或哈希；
- 明确区分“自动测试通过”和“存在非阻塞语义建议”。
