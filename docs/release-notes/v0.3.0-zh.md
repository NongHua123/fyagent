# FyAgent v0.3.0

[English](v0.3.0-en.md) | [日本語](v0.3.0-ja.md)

> [!WARNING]
> **FyAgent v0.3.0 明确为无签名发布。** Windows 可执行文件和 MSI 的
> Authenticode 状态必须为 `NotSigned`；macOS 应用没有 Developer ID 签名或
> 公证。因此 Windows SmartScreen 和 macOS Gatekeeper 可能发出警告或阻止首次启动。
> 安装前请核对下文规定的精确附件名称与证据。

> [!IMPORTANT]
> **验证状态：** 本文是 v0.3.0 的冻结发布合同和中文说明。安装前必须确认
> Release 精确提供下文 13 个附件，并验证 manifest、构建元数据和 attestation。
> 发布后独立重新下载的复核结果只会在完成后写入 closeout 证据；本文本身不表示
> closeout 复核已经完成。

## 重点变化

- **合并 CC Switch v3.19.2：** 从 annotated tag `v3.19.2` 完整保留上游 ancestry，
  以独立双亲 merge commit 合入。FyAgent 产品版本固定为 `0.3.0`，不会改名为上游版本。
  详见[来源台账](../upstream/cc-switch-v3.19.2.md)。
- **原生构建边界：** 退役 Linux/WSL 到 Windows、macOS 的本地交叉构建；本地只构建
  当前宿主。正式 Windows x64/ARM64、Linux x64/ARM64、macOS Universal 资产只由
  对应原生 GitHub runner 生成，不使用 QEMU 降级。
- **mise + uv 开发环境：** 建立 canonical `mise run` 任务 API，固定 Node 24.19.0、
  pnpm 10.12.3、Rust 1.97.1、Python 3.14.7 的权威来源，以 checksum lock 固定 uv，
  并由 uv 独占管理 `.venv` 与 Python 依赖锁。
- **自动 CI 与 Labeler：** 恢复 PR/main 自动 CI、稳定名称 `CI / Required` 汇总门禁，
  以及不 checkout、不执行 PR 代码的 base-repository Labeler。真实远程事件证据仍是
  发布门禁。
- **原生 Fetch 与 DEP0040：** 删除 `cross-fetch` 及
  `node-fetch@2 → whatwg-url@5 → tr46@0.0.3 → punycode` 旧链路；通过 MSW 与
  Tauri mock 验证 Node 原生 Fetch 的成功、文本错误、空响应和跨 realm 行为，并把
  弃用告警升级为失败。
- **失败关闭的发布事务：** 手动 preflight 构建并 attest 完整矩阵但绝不发布；正式
  `v0.3.0` 路径绑定 tag、产品版本、source、可信 workflow、`origin/main` ancestry
  与同 SHA Required CI，验证精确资产和证据后才执行 draft 到稳定 Release 的事务。

## 下载与无签名安装

### Windows

选择与机器架构一致的 MSI。应用与 MSI 明确无签名，SmartScreen 可能显示未知发布者
警告。继续前请核对精确文件名、`download-manifest.json` 摘要、构建元数据与
attestation 证据。不要关闭 SmartScreen，也不要削弱组织管理的安全策略。

### macOS

DMG 与 ZIP 包含同一份 Universal 应用。因为 v0.3.0 没有 Developer ID 签名或公证，
macOS 可能阻止首次启动。先尝试打开 FyAgent，然后使用 Apple 支持的“**系统设置 →
隐私与安全性 → 仍要打开**”流程并确认提示。不要关闭 Gatekeeper 或移除隔离属性。

### Linux

选择与宿主匹配的 x86_64 或 arm64 包。AppImage、DEB、RPM 都是正式必需格式。
Flatpak 仅是本地诊断转换，不属于 v0.3.0 的十个安装资产。

## 精确 Release 附件合同

正式 Release 必须精确包含以下 **10 个安装资产**：

```text
FyAgent-0.3.0-macOS.dmg
FyAgent-0.3.0-macOS.zip
FyAgent-0.3.0-Windows.msi
FyAgent-0.3.0-Windows-arm64.msi
FyAgent-0.3.0-Linux-x86_64.AppImage
FyAgent-0.3.0-Linux-x86_64.deb
FyAgent-0.3.0-Linux-x86_64.rpm
FyAgent-0.3.0-Linux-arm64.AppImage
FyAgent-0.3.0-Linux-arm64.deb
FyAgent-0.3.0-Linux-arm64.rpm
```

另外只能包含以下 **3 个证据附件**：

```text
download-manifest.json
build-metadata.json
artifact-attestation.sigstore.json
```

总数必须是 **13**。`download-manifest.json` 记录每个安装资产的 SHA-256、大小、平台、
架构、格式、source、tag 和最终 URL；`build-metadata.json` 把五组原生目标绑定到
runner、工具链、容器、workflow、source 与 Required CI；Sigstore bundle 覆盖十个
安装资产和两份 JSON 证据。不会发布第十四个独立 checksum 文件。缺失、重复、改名、
空文件或额外附件都会阻止发布。

## 兼容性

FyAgent v0.3.0 不新增运行时 API、数据库或用户数据迁移，并保持以下合同兼容：

- 数据库 schema **16** 与 `~/.fyagent/fyagent.db`；
- `~/.fyagent` 设置、skills 与自动备份行为；
- `fyagent://` deep link 与 bundle identifier `com.fyagent.desktop`；
- 现有 `FYAGENT_*` 环境合同和 Windows 受保护安装边界。

升级前仍应备份重要配置。原生构建失败、附件不全、身份/数据路径漂移或 attestation
缺失都是 NO-GO，不能用精简矩阵替代。

## 供应链模型与已接受风险

v0.3.0 没有 Windows/macOS 签名凭据、公证、staple、signed mode、受保护 Release
environment、branch protection 或 branch/tag ruleset。最小权限与 eligibility 由
workflow 代码强制：默认 `contents: read`、聚焦的 CI/Labeler/attestation/publish 权限、
完整 SHA Actions、精确仓库/workflow/source 身份和附件 allowlist。

这比管理员强制的规则和 environment 审批更弱，是 v0.3.0 明确接受的残余供应链风险。
项目不会声称 `main`、tag 或 Release 受管理员保护。恢复签名或增强仓库治理必须走后续
独立决策。

## 验证边界

本地合同检查只证明源码和 workflow 结构。正式发布必须对同一个精确 `main` source SHA
取得以下真实证据：

1. 自动 `CI / Required` 成功；
2. 五目标组无签名 preflight 成功且没有创建 Release；
3. 精确 `v0.3.0` tag 触发正式 workflow；
4. 稳定、非 prerelease 的公共 Release 精确包含 13 个附件；
5. 独立重新下载并核对名称、数量、版本、架构、大小、SHA-256、Windows `NotSigned`、
   macOS 无签名/未公证状态和 attestation bundle。

第 1–4 项是发布门禁，第 5 项是发布后独立 closeout 复核，只能在完成后记录。
无论本文在发布前从仓库阅读，还是在发布后作为 Release Notes 阅读，都不能单独证明
上述任何一项。安装前请核对精确 13 个附件及其证据；在项目记录结果前，不得推定
独立 closeout 复核已经完成。
