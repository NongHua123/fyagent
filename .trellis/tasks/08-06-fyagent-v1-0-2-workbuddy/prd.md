# FyAgent v1.0.2 修复与增强

## 目标与用户价值

以 `docs/fyagent/dev/v1-0.2/` 为当前产品与设计基线，交付安全、可回归、
可审计的 v1.0.2 修复与增强。用户应能安全地使 Codex 配置生效、维护
WorkBuddy 模型配置、在稳定的桌面布局中完成操作，并在 Windows 正式发布时
获得经过最小权限补偿的提升运行边界。

## 权威输入与已确认决策

- `docs/fyagent/dev/v1-0.2/README.md` 与 `01`–`08` 是本任务的需求、交互、
  架构、数据安全、实施、验收和 ADR 输入。需求编号 `CR-*`、`WB-*`、
  `CV-*`、`UI-*`、`WIN-*`、`NFR-*`、`QA-*` 是代码和测试追踪主键。
- 用户确认：v1.0.2 覆盖最初版设计中与其冲突的条款；未被 v1.0.2 明确改变
  的行为继续沿用。`docs/fyagent/dev/v1/` 改名为
  `docs/fyagent/dev/v1-0.0/`，并作为最初版历史设计保留，而非永久产品基线。
- 用户确认：最终规划获批后可直接执行本任务，但 Trellis 的最终规划摘要仍是
  启动实施前的阶段门禁。
- 用户限制：不得在本机进行真实 Codex / ChatGPT 桌面应用测试或操作；不得
  启动、关闭、重启、安装、升级或配置真实应用，也不得读写真实用户 Codex
  配置。相关验证必须使用 fixture、fake 平台适配器、mock IPC 和隔离单元测试。

## 范围内的需求

### 文档与基线治理

- 将 19 份最初版 Markdown 原样从 `docs/fyagent/dev/v1/` 迁至
  `docs/fyagent/dev/v1-0.0/`，保持相对链接和历史正文不变。
- 更新活动 Trellis 规范和当前任务说明，使 v1.0.2 成为当前范围的权威输入；
  `v1-0.0` 与 `v1-0.1` 仅在未被覆盖的历史/兼容契约中引用。
- 保留 `.trellis/tasks/archive/`、Git commit/tag/branch、release note、旧
  zip 校验记录和协议/API 中与目录无关的 `v1` 字符串，禁止全局文本替换。

### WorkBuddy（WB-001–025、UI-001–004）

- 支持根数组与 `{ "models": [] }` 对象根，保持原根形状、未知字段、条目
  顺序和对象键顺序；损坏配置失败关闭、不改写原文件。
- 只投影已有的唯一 ID，新增即时搜索、刷新、远程结果默认选中、过滤后保留
  选择及一次性覆盖确认。
- 新建与覆盖在 revision 守护下以单一原子事务完成；覆盖仅更新 `url` 与
  `apiKey`，历史重复 ID 全部更新但不整理；`availableModels` 按三分支规则
  保守增量维护。
- API Key 仅保留在 WorkBuddy 页面局部内存，保存、失败和冲突后保持，离页或
  关窗清除；不得返回、缓存、记录或从配置回填密钥。
- WorkBuddy 使用标准全宽页面壳层，稳定滚动；只展示脱敏/相对配置位置，
  不向 WebView、日志或截图暴露真实用户目录全路径。

### Codex 运行时（CR-001–020、CV-001–010）

- 从真实 live 配置变化出发，在唯一或歧义的精确身份运行状态下提供一次风险
  确认；确认后重新枚举、进程去重、强制关闭全部精确匹配实例、确认退出后
  仅启动一次，任何关闭失败均不得启动。
- 只使用 Windows 精确 PFN / macOS 精确 Bundle ID；不得退化为名称、标题或
  路径匹配。无可信身份时返回 `untrusted_target` 并只允许手动处理。
- 以 opaque、短期、一次性能力令牌保护强制重启及重试，且令牌绑定命令与
  请求摘要；候选集合变化允许固定比较器重新计算，但不允许扩大身份范围。
- 将本地/远程版本表示为显式判别状态，正确区分首次加载、后台刷新、有旧值
  的刷新失败、首次失败、无平台产物和元数据异常。

### 应用壳层与窗口（UI-005–020）

- 顶部栏顺序为品牌/导航、P1、P2/More、弹性 AppSwitcher、固定最右主操作槽。
  Provider 显示 `+`，WorkBuddy 保留完全同宽且不可交互/不可访问的空槽。
- 使用容量测量形成版本化最小宽度常量，受限空间按 P2、Profile、非当前应用、
  紧凑 Profile 的顺序降级；P0 不得裁剪、丢失或引入页面横向滚动。
- 在隐藏阶段恢复、钳制和迁移窗口状态，对工作区/DPI 变化合并处理；合法用户
  尺寸不被无条件放大。

### Windows 安全与发布（WIN-001–029）

- 正式构建使用 `requireAdministrator`、per-machine 安装、安全目录 ACL、
  Authenticode 和时间戳，删除 Portable 产物；测试构建保持普通权限。
- 在 Tauri/业务初始化前建立单业务实例和安全激活转发；Windows 禁用并清理
  自启，但保持可配置的关闭到托盘。
- 浏览器、文件管理器、终端、编辑器和 Codex 等普通外部应用从提升主进程
  以交互用户普通权限启动；仅明确定义的 CLI 安装/升级是管理员白名单例外。
- 以 `invoke_handler` 为清单进行 Q0–Q5 分类，收紧 Capability/CSP，后端复验
  参数与状态，并以一次性能力令牌保护管理员和破坏性动作。

### 验收与证据（QA-001–007）

- 添加 Rust/React 覆盖、有限的 desktop E2E、几何与关键区域视觉回归、四语
  文案完整性与发布证据结构；普通 CI 仍只允许手动触发。
- 真实应用进程、真实 UAC、真实安装器、真实第三方服务、真实 WorkBuddy/Codex
  用户文件和真实签名发布均不是本机测试项；它们必须在受控候选环境人工验收。

## 不在范围内

- WorkBuddy 模型删除、排序、逐项编辑、完整管理器，以及安装、检测、升级、
  启动、关闭或重启 WorkBuddy。
- ChatGPT Classic、Codex CLI、IDE 插件、模糊进程匹配、Windows 非提权启动器、
  全用户 Codex 部署、局域网代理 token、深链接 API Key 禁用，或 PR/push CI。
- 重写 Git 历史、归档任务证据、tag、release note 或仅因文档目录改名而改变
  `fyagent://v1`、`/v1` API 路径和依赖版本。

## 验收标准

- 每一组 `CR/WB/CV/UI/WIN/NFR/QA` 编号在子任务 PRD 和测试中具有关联项；
  文档包的 P0 场景均有自动测试或明确标注的受控人工验收。
- 目录迁移后新目录存在、旧目录不存在，19 份历史 Markdown 内容与 `HEAD`
  中原文件逐字一致，活动规范不再将旧 v1 作为当前冻结基线。
- WorkBuddy 保留数据和密钥边界、Codex 不放宽身份、顶部栏 P0 永不被裁剪、
  Windows 提权不扩散到普通外部应用。
- 类型检查、格式检查、单元测试、选择性的 mock desktop 检查以及
  `git diff --check` 全部通过；不执行任何真实 Codex / ChatGPT 操作。
- Windows/macOS 运行时、安装器、签名、ACL、DPI、视觉基线和真实应用重启的
  未执行项目在最终证据中明确列为受控环境人工验收，不得声明本机通过。

## 风险与延期

- Windows PFN 已通过只读包元数据与既有 allowlist 对齐；macOS Bundle ID 和
  所有真实应用运行路径仍必须在受控候选环境验证。
- Authenticode 证书、时间戳服务、发布密钥和真实签名验证依赖外部发布环境；
  代码/工作流可实现门禁，但不能在本机声称产物已签名。
- 视觉差异阈值、最终最小宽度、发布环境截图和真实 UAC 行为依赖受控的稳定
  夹具；开发阶段只能验证其代码和 fixture 接线。
