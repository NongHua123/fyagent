# WorkBuddy v1.0.2 数据与体验

## 目标

让用户安全、可预期地查看和维护 WorkBuddy 模型连接，同时保持 WorkBuddy 是
独立顶层配置域，而不是 Provider 或完整模型管理器。

## 范围与需求

- 实现 WB-001–004 的双根 JSON、严格校验、同形状写回和未知字段/顺序保留。
- 实现 WB-005–013 的已有 ID 投影、即时搜索、远程搜索、默认全选及过滤选择。
- 实现 WB-014–018 的一次覆盖确认、revision 竞态终止、原子混合写入和仅
  `url`/`apiKey` 覆盖。
- 实现 WB-019–025 的 API Key 局部生命周期、`availableModels` 三分支、固定
  官网入口及安全错误映射。
- 实现 UI-001–004：标准全宽壳层、响应式卡片、稳定单主滚动和无页面横滚。

## 约束与非范围

- 不增加删除、排序、逐项编辑或 WorkBuddy 安装/启动能力；不把它接入 Provider。
- 不返回/缓存完整配置、API Key、URL、Vendor、能力或真实用户绝对路径。
- 不访问真实用户 WorkBuddy 文件或第三方模型端点；测试使用临时 HOME、fixture
  和 mock HTTP。

## 验收标准

- [ ] 根数组/对象根/缺失文件按 WB-001–004 保留形状、字段和顺序；非法结构
  不写主文件。
- [ ] 已有 ID、远程筛选、选择与一次性覆盖确认匹配 WB-005–018；revision
  变化或 token 失效不写文件。
- [ ] Key 在保存/失败/冲突后保留，离页/关窗清除；日志、DTO、query cache、
  fixture 和截图不含秘密。
- [ ] 页面无白边、无横滚、卡片布局/滚动/官网入口符合 UI-001–004/WB-024–025；
  四语无缺键。
- [ ] Rust 与 React P0 测试、类型/格式检查和 `git diff --check` 通过。
