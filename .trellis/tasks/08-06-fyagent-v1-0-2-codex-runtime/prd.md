# Codex v1.0.2 重启与版本状态

## 目标

让成功改变 live Codex 配置的用户得到安全、简单且可重试的重启结果；同时让
本地/远程版本的加载、刷新和错误状态诚实可见，而不泄露进程或安装细节。

## 范围

- CR-001–020：精确身份、非唯一状态的一次确认、固定安装选择、全量匹配实例
  强制关闭、一次启动、竞态/失败处理、脱敏结果对话框和直接重试。
- CV-001–010：本地/远程版本的显式判别状态、加载/后台刷新/失败状态及按钮
  可用性。

## 强制约束

- Windows 只接受精确 PFN，macOS 只接受精确 Bundle ID；不得用显示名、进程名、
  标题或路径作 fallback。无可信身份为 `untrusted_target`，零进程操作。
- 用户确认后直接强制关闭，不执行正常退出或第二次强制确认；任何关闭失败都
  不启动。普通保存路径发现未运行时不自动启动。
- 前端不显示 PID、候选数、路径、版本或错误阶段；所有令牌 opaque、短期、
  一次性并在后端复验。
- 不在本机运行真实 Codex/ChatGPT、读取其配置、调用 PackageManager 或触发
  进程 API；所有测试使用 fake platform、fixture 和注入时钟。

## 验收标准

- [ ] CR-T01–13 和 CR-UI01–06 的 fake/fixture 测试覆盖进程去重、多实例、
  比较器、身份硬停止、token、失败不启动、一次启动与用户反馈。
- [ ] CV-T01–05 覆盖首次加载、刷新、有旧值失败、无缓存失败、无平台产物和
  元数据异常；界面不再以 nullable 值误报状态。
- [ ] Mac 未验证真实 Bundle ID 时保持 `untrusted_target`，且测试证明不会
  退化匹配；Windows 身份只以 allowlist/fixture 验证，不执行真实应用操作。
- [ ] 前后端 DTO、四语言、可访问性、类型/格式/单测和 `git diff --check` 通过。

## 外部验证边界

真实进程、安装、重启、UAC 和目标应用身份只在受控候选环境人工验证；本任务
本机的完成证据仅涵盖 fake/fixture 行为与静态安全约束。
